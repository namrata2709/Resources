AWS Well-Architected Framework (WAF)

✅ Overview

The AWS Well-Architected Framework is a set of best practices to design, build, and review workloads on AWS. It answers:

  • Is your application deployed correctly on AWS?
  • Is your application built using AWS best practices?
  • Are you optimizing costs while maintaining performance?

💡 Important Distinction: AWS WAF (Web Application Firewall) is a separate security service. The Well-Architected Framework is an architectural guidance framework.

🏛️ The Six Pillars

Figure 1: AWS Well-Architected Framework - Six Pillars

Pillar Focus Key Question
Operational Excellence Run and monitor systems How do you run and monitor systems to deliver business value?
Security Protect information and systems How do you protect data, systems, and assets?
Reliability Ensure workload performs correctly How do you ensure a workload performs as intended?
Performance Efficiency Use resources efficiently How do you use computing resources efficiently?
Cost Optimization Avoid unnecessary costs How do you run systems at the lowest cost?
Sustainability Minimize environmental impact How do you minimize environmental impacts?

1️⃣ Operational Excellence

Key Principles:

  • Operations as code (Infrastructure as Code)
  • Frequent, small, reversible changes
  • Anticipate failure scenarios
  • Learn from operational failures

Supporting AWS Services:

Service Purpose Use Case
CloudFormation Infrastructure as Code Automated resource deployment
CloudWatch Monitoring and logging Track metrics and logs
AWS Config Configuration tracking Compliance and auditing
CloudTrail API call logging Audit trail for security

2️⃣ Security

Design Principles:

  • Implement strong identity foundation (IAM)
  • Enable traceability (logging)
  • Apply security at all layers
  • Automate security best practices
  • Protect data in transit and at rest
  • Prepare for security events

3️⃣ Reliability

Design Principles:

  • Automatically recover from failure
  • Test recovery procedures
  • Scale horizontally for availability
  • Stop guessing capacity needs
  • Manage change through automation
Component AWS Implementation Example
High Availability Multi-AZ deployment RDS Multi-AZ, ELB across AZs
Disaster Recovery Cross-region replication S3 Cross-Region Replication
Auto Scaling EC2 Auto Scaling Groups Scale based on metrics
Backup AWS Backup Automated EBS snapshots

4️⃣ Performance Efficiency

Key Considerations:

  • Democratize advanced technologies
  • Go global in minutes
  • Use serverless architectures
  • Experiment more often
  • Consider mechanical sympathy

5️⃣ Cost Optimization

Strategy Implementation Potential Savings
Right-sizing Use appropriate instance types 20-40%
Reserved Instances 1-3 year commitments Up to 75%
Spot Instances For fault-tolerant workloads Up to 90%
Auto Scaling Scale down during low usage 30-50%

❌ Common Mistake: Leaving development/test resources running 24/7. Use Lambda + EventBridge to automate start/stop schedules.

6️⃣ Sustainability

Design Principles:

  • Understand your impact (Customer Carbon Footprint Tool)
  • Establish sustainability goals
  • Maximize utilization (right-sizing)
  • Use managed services (AWS operates efficiently at scale)
  • Reduce downstream impact

Cloud Adoption Framework (CAP)

Figure 2: Cloud Adoption Framework - Four Phase Journey (Envision → Align → Launch → Scale)

✅ Overview

The AWS Cloud Adoption Framework provides structured guidance for organizations planning cloud migration. It addresses: "Is our organization ready to move to the cloud?"

⚠️ Key Concept: Cloud migration is not just infrastructure change—it's organizational transformation affecting people, processes, and technology.

🎯 Why CAP is Needed

Common Problems Without Proper Planning:

  • Applications crash frequently after migration
  • Unexpected cost increases (bill shock)
  • Security vulnerabilities and compliance gaps
  • Poor performance despite using cloud resources
  • Lack of skilled personnel

❌ Root Cause: Organizations fail in cloud not due to technology, but due to poor planning and poor design.

Security Protection & compliance CISO, Security Managers, Compliance

1️⃣ Business Perspective

Purpose: Ensure IT investments align with business goals and demonstrate measurable value.

Key Questions:

  • Why are we moving to cloud? (Business case)
  • What business outcomes do we expect?
  • How will we measure ROI?
  • What is our cloud strategy?

2️⃣ People Perspective

Purpose: Prepare workforce through training, communication, and change management.

Area Activities Example
Skills Assessment Identify skill gaps Team knows on-premises, needs AWS training
Training Programs Upskill existing staff AWS Restart, AWS Training & Certification
Change Management Manage resistance Communication plan, stakeholder buy-in
New Hiring Recruit cloud expertise Hire AWS Solutions Architects

3️⃣ Governance Perspective

Purpose: Manage and measure cloud investments while minimizing risks.

Key Components:

  • Cloud Center of Excellence (CCoE) establishment
  • Policies and standards definition
  • Compliance and regulatory requirements
  • Cost management and optimization
  • Risk management framework

4️⃣ Platform Perspective

Purpose: Design, build, and optimize cloud architecture.

Decision Area Considerations
Compute Strategy EC2 vs Lambda vs Containers (ECS/EKS)
Storage Strategy S3 vs EBS vs EFS vs FSx
Database Strategy RDS vs DynamoDB vs Aurora vs Redshift
Networking Design VPC design, hybrid connectivity, CDN

5️⃣ Security Perspective

Purpose: Ensure workloads meet security, resiliency, and compliance requirements.

Focus Areas:

  • Identity and Access Management (IAM)
  • Data protection (encryption at rest and in transit)
  • Infrastructure protection (network security)
  • Detective controls (logging, monitoring)
  • Incident response procedures
  • Compliance (GDPR, HIPAA, PCI-DSS)

6️⃣ Operations Perspective

Purpose: Ensure reliable cloud operations with health monitoring and agile response.

Best Practices:

  • Automated deployments (CI/CD pipelines)
  • Infrastructure as Code (CloudFormation, Terraform)
  • Monitoring and alerting (CloudWatch, SNS)
  • Incident management and post-mortems
  • Disaster recovery testing

  • CAF ensures organizational readiness before migration
  • Addresses both business and technical aspects
  • Involves stakeholders across entire organization
  • Use CAP before migration; use WAF after migration

System & Network Hardening

✅ Core Security Principle

⚠️ Fundamental Truth: Security is about controlling access at TWO critical points:

  • Before reaching the system → Network Hardening
  • After reaching the system → System Hardening

Figure 4: Defense in Depth - Multiple Security Layers Protecting Data

🌐 Network Hardening

Definition

Network Hardening controls access before someone reaches your server/system.

💡 Core Concept: If attackers cannot reach your system, they cannot attack it. Network hardening prevents unauthorized connections.

Key Questions Addressed

  • Who is allowed to connect? (IP addresses, user groups)
  • From where can they connect? (Specific IPs, VPNs)
  • On which port? (SSH port 22, HTTP port 80, HTTPS port 443)

Network Hardening Components

Component AWS Implementation Purpose
Firewall Security Groups Stateful firewall at instance level
ACLs Network ACLs (NACLs) Stateless firewall at subnet level
Port Blocking Security Group rules Close unused ports
Geo-blocking AWS WAF Block traffic from specific countries
Network Segmentation Public/Private Subnets Isolate resources by sensitivity

Figure 5: Network Hardening Architecture - Key Components

⚙️ Practical Implementation

Method 1: AWS CLI
# Create security group
aws ec2 create-security-group \
    --group-name web-server-sg \
    --description "Security group for web servers" \
    --vpc-id vpc-12345678

# Allow HTTP from internet
aws ec2 authorize-security-group-ingress \
    --group-id sg-12345678 \
    --protocol tcp \
    --port 80 \
    --cidr 0.0.0.0/0

# Allow SSH only from admin IP
aws ec2 authorize-security-group-ingress \
    --group-id sg-12345678 \
    --protocol tcp \
    --port 22 \
    --cidr 203.0.113.25/32

# View security group rules
aws ec2 describe-security-groups \
    --group-ids sg-12345678
Method 2: AWS Console (GUI)
  1. Navigate to EC2 Dashboard → Security Groups
  2. Click Create security group
  3. Enter name: web-server-sg
  4. Select VPC
  5. Under Inbound rules, click Add rule:
    • Type: HTTP | Source: 0.0.0.0/0
    • Type: SSH | Source: My IP
  6. Click Create security group
  7. Attach to EC2 instances as needed

✅ Example Configuration:

  • Port 80 (HTTP) from 0.0.0.0/0 (internet)
  • Port 443 (HTTPS) from 0.0.0.0/0 (internet)
  • Port 22 (SSH) from admin IP only
  • Block all other ports (default deny)

💻 System Hardening

Definition

System Hardening controls what users can do after reaching your system.

💡 Core Concept: Even after gaining access, system hardening limits what users can see, modify, or execute.

Figure 7: System Hardening - Layered Security Architecture

System Hardening Focus Areas

Category What It Controls Implementation
User Management Who can log in IAM users, Linux accounts, sudo privileges
Service Hardening Which services run Stop unnecessary services (systemctl)
OS Hardening Operating system security Security patches, disable root login
Application Security What software runs Remove unnecessary packages, updates
File Permissions Who can read/write files chmod, chown, ACLs
Logging & Monitoring Track activities CloudWatch Logs, syslog, audit logs
html

Figure 7b: Five Types of System Hardening - Server, Software, Operating System, Database, and Network Hardening

1️⃣ User Management

AWS CLI - IAM User Management
# Create IAM user
aws iam create-user --user-name developer1

# Attach read-only policy
aws iam attach-user-policy \
    --user-name developer1 \
    --policy-arn arn:aws:iam::aws:policy/ReadOnlyAccess

# Enable MFA
aws iam enable-mfa-device \
    --user-name developer1 \
    --serial-number arn:aws:iam::123456789012:mfa/developer1 \
    --authentication-code1 123456 \
    --authentication-code2 789012
AWS Console - IAM User Creation
  1. Navigate to IAM Dashboard → Users
  2. Click Add users
  3. Enter username: developer1
  4. Select access type: Programmatic access and/or AWS Management Console access
  5. Click Next: Permissions
  6. Select Attach existing policies directly
  7. Choose ReadOnlyAccess policy
  8. Click Next: Tags → Next: Review → Create user
  9. Enable MFA from user security credentials tab
Linux Server - User Management
# Create new user
sudo adduser developer1

# Add to specific group
sudo usermod -aG developers developer1

# Disable root SSH login
sudo nano /etc/ssh/sshd_config
# Set: PermitRootLogin no
sudo systemctl restart sshd

# View active users
w
who

2️⃣ Service Hardening

Principle: Stop and disable unnecessary services to reduce attack surface.

# List running services
sudo systemctl list-units --type=service --state=running

# Stop unnecessary service
sudo systemctl stop bluetooth.service

# Disable from starting at boot
sudo systemctl disable bluetooth.service

# Check status
sudo systemctl status apache2

❌ Common Mistake: Leaving default services running (FTP, Telnet, unused databases) which are common attack vectors.

3️⃣ Operating System Hardening

# Ubuntu/Debian - Update system
sudo apt update
sudo apt upgrade -y
sudo apt dist-upgrade -y

# Amazon Linux 2 - Update system
sudo yum update -y

# Enable automatic security updates (Ubuntu)
sudo apt install unattended-upgrades
sudo dpkg-reconfigure --priority=low unattended-upgrades

4️⃣ File Permissions

Permission Numeric Meaning
Read (r) 4 View file contents
Write (w) 2 Modify file
Execute (x) 1 Run file as program 
# Secure SSH private key
chmod 400 ~/.ssh/id_rsa

# Web directory permissions
chmod 644 /var/www/html/index.html

# Script executable by owner only
chmod 700 /home/user/script.sh

# Change file owner
sudo chown user:group filename

✅ Recommended Permissions:

  • SSH keys: 400
  • Configuration files: 640
  • Executables: 750
  • Web content: 644
  • Sensitive directories: 700

5️⃣ Logging and Monitoring

AWS CLI - Enable CloudWatch Logs
# Install CloudWatch agent
wget https://s3.amazonaws.com/amazoncloudwatch-agent/linux/amd64/latest/AmazonCloudWatchAgent.zip
unzip AmazonCloudWatchAgent.zip
sudo ./install.sh

# Configure and start agent
sudo /opt/aws/amazon-cloudwatch-agent/bin/amazon-cloudwatch-agent-config-wizard
AWS Console - CloudWatch Logs Setup
  1. Navigate to CloudWatch → Logs → Log groups
  2. Click Create log group
  3. Enter name: /aws/ec2/web-servers
  4. On EC2 instance, install and configure CloudWatch agent
  5. Configure agent to send logs to created log group
  6. View logs in CloudWatch Logs console
Linux - System Logging
# View login attempts
sudo tail -f /var/log/auth.log  # Ubuntu
sudo tail -f /var/log/secure    # RHEL/CentOS

# View system logs
sudo journalctl -xe

# View failed login attempts
sudo grep "Failed password" /var/log/auth.log

✅ Key Takeaways:

  • Network Hardening: Control access BEFORE reaching system
  • System Hardening: Control access AFTER reaching system
  • Both are essential for defense-in-depth security
  • Follow principle of least privilege at all layers
  • Regular audits and updates are critical

AWS Certification Exam Preparation

✅ Exam Overview

AWS Certified Cloud Practitioner is a foundational-level certification validating understanding of AWS Cloud, services, and terminology.

Exam Detail Information
Exam Code CLF-C02
Duration 90 minutes (+ 30 min ESL accommodation)
Questions 65 (multiple choice / multiple response)
Passing Score 700 out of 1000 points (~70%)
Cost $100 USD (+ taxes ≈ $118-120)
Validity 3 years
Format Online proctored OR test center

⚠️ Scoring Note: Questions have different weightage (internal AWS calculation). Focus on answering all questions correctly.

📋 Registration Process

Step 1: Create AWS Training Account

  1. Visit: https://www.aws.training
  2. Click Sign In → Create new account
  3. Enter email, name (MUST match government ID exactly)
  4. Verify email address
  5. Complete profile information

❌ Critical: Name must match government ID exactly. Mismatches prevent exam access. Contact AWS Support immediately if incorrect.

Step 2: Request Exam Accommodation

  1. Log in to AWS Training portal
  2. Navigate to Certification → Exam Accommodations
  3. Click Request Accommodation
  4. Select: ESL +30 Minutes
  5. Submit (usually approved within 24-48 hours)

💡 Recommendation: Always request accommodation. Extra 30 minutes reduces pressure and improves performance.

Step 3: Schedule Exam

  1. Go to Certification → Schedule an Exam
  2. Select AWS Certified Cloud Practitioner (CLF-C02)
  3. Choose format:
    • Test Center: Professional environment, no internet worries
    • Online Proctored: Flexible timing, taken from home
  4. Select date and time
  5. Apply voucher code (if provided)
  6. Complete registration

🏢 Test Center Exam

Advantages

  • No internet connection concerns
  • No technical setup required
  • Professional exam environment
  • Power backup available

On Exam Day

  1. Arrive 30 minutes early
  2. Bring government-issued photo ID (passport, driver's license, Aadhaar)
  3. Check-in: ID verification, photo, signature
  4. Store belongings in locker
  5. Not allowed: phones, smartwatches, bags, notes
  6. Test center provides: computer, headphones (optional), scratch paper
  7. Complete exam
  8. Receive preliminary result immediately

💻 Online Proctored Exam

System Requirements

Requirement Specification
Computer Personal laptop (NOT work computer)
Internet Minimum 2 Mbps (5G hotspot recommended)
Webcam Built-in or external (720p minimum)
Microphone Built-in or external
Power Fully charged + plugged in
Room Private, quiet, well-lit

⚠️ Critical Recommendation from Training:

  • Laptop MUST be charged AND plugged in
  • Use 5G mobile hotspot (more reliable than Wi-Fi)
  • Why? Prevents disconnection from power/internet failure

Pre-Exam Setup

  1. System Test (run 1 week, 3 days, and 2 hours before exam):
    • Download OnVUE application
    • Test internet speed, webcam, microphone
  2. Room Preparation:
    • Clear desk completely
    • Remove posters, sticky notes
    • Close doors and windows
    • Silence mobile phone (keep for ID upload)

Exam Day Timeline (Start 30 Minutes Early)

Time Before Activity
30 min Launch OnVUE, run system test
20 min Start check-in process
15 min Upload ID photos via mobile link
10 min Room scan with webcam
5 min Proctor reviews setup
0 min Exam begins

Check-In Process

  1. System Test: Verify internet, webcam, microphone
  2. Room Scan: Hold laptop, show 360° view of room
  3. ID Verification: Upload ID photos + selfie + 4 room photos via mobile
  4. Proctor Review: Proctor confirms setup (2-5 minutes)
  5. Exam Released: Begin exam

❌ Prohibited Actions (Exam Termination):

  • Standing up or leaving chair
  • Looking away from screen
  • Talking or mouthing words
  • Someone else entering room
  • Wearing headphones/earbuds
  • Background noise

Best Practices Summary

For Well-Architected Framework

  • Use AWS Well-Architected Tool for automated reviews
  • Focus on all six pillars equally
  • Implement continuous improvement cycles
  • Don't neglect sustainability pillar

For Cloud Adoption Framework

  • Engage stakeholders from all six perspectives
  • Invest in training (People perspective)
  • Establish Cloud Center of Excellence (Governance)
  • Don't skip organizational readiness assessment

For Network Hardening

  • Default deny all, explicitly allow only required traffic
  • Separate public and private subnets
  • Use Security Groups (stateful) at instance level
  • Use NACLs (stateless) at subnet level
  • Implement geo-blocking for high-risk regions

For System Hardening

  • Principle of least privilege for all users
  • Disable root SSH login
  • Use SSH keys instead of passwords
  • Stop and disable unnecessary services
  • Apply security patches regularly
  • Enable automatic security updates
  • Set correct file permissions (400 for SSH keys)
  • Enable comprehensive logging and monitoring

For Exam Success

  • Schedule within 1 month of voucher receipt
  • Take minimum 3 practice exams scoring 80%+
  • For online exam: Prioritize technical stability
  • Read questions carefully (keywords: "most cost-effective", "most secure")
  • Use elimination method for uncertain questions
  • Mark questions for review, don't waste time
