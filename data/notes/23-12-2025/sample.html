Understanding Amazon EC2

🏨 Real-Life Analogy

💡 Think of EC2 like renting hotel rooms:

  • Different room types (standard, deluxe, suite) = Different instance types (t3.micro, m5.large, c5.xlarge)
  • Pay only for nights stayed = Pay only for compute time used
  • Check-in/Check-out anytime = Launch and terminate instances on demand
  • Room service options = Additional storage, networking, and services

For example: Just like booking a hotel room for a weekend trip, you can launch an EC2 instance for a short project, use it, and terminate it when done—paying only for what you used.

What is EC2?

Amazon Elastic Compute Cloud (EC2) is a web service that provides secure, resizable compute capacity in the cloud. It's designed to make web-scale cloud computing easier for developers by providing complete control over computing resources.

Why EC2 Matters

  • Scalability: Scale up or down based on demand
  • Cost-Effective: Pay only for what you use
  • Flexibility: Choose from various instance types optimized for different use cases
  • Control: Full administrative access to your instances

Launching an EC2 Instance

⚙️ Practical Implementation

Method 1: AWS CLI

aws ec2 run-instances \
    --image-id ami-0c55b159cbfafe1f0 \
    --instance-type t3.micro \
    --key-name MyKeyPair \
    --security-group-ids sg-0123456789abcdef0 \
    --subnet-id subnet-0bb1c79de3EXAMPLE \
    --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=MyWebServer}]' \
    --region us-east-1

What this command does: Launches a new t3.micro EC2 instance using the specified AMI (Amazon Machine Image) in the us-east-1 region, with proper security and networking configuration.

Method 2: AWS Console (GUI)

  1. Open AWS Management Console and navigate to EC2 Dashboard
  2. Click Launch Instance button (orange button in top right)
  3. Name your instance: Enter "MyWebServer"
  4. Choose AMI:
    • Select Amazon Linux 2023 (Free tier eligible)
    • Or choose from Quick Start options
  5. Select Instance Type:
    • Choose t3.micro (1 vCPU, 1 GB RAM)
    • Free tier eligible
  6. Key pair (login):
    • Click Create new key pair
    • Name: "MyKeyPair"
    • Type: RSA, Format: .pem
    • Download and save securely
  7. Network settings:
    • VPC: Use default VPC
    • Subnet: No preference
    • Auto-assign public IP: Enable
  8. Firewall (security groups):
    • Create security group
    • Allow SSH (port 22) from My IP
    • Allow HTTP (port 80) from anywhere
  9. Storage: Keep default 8 GB gp3 volume
  10. Click Launch Instance
  11. Wait 2-3 minutes for instance to reach Running state
  12. Verify: Instance shows "2/2 checks passed"

✅ Best Practice: Always add descriptive tags to your instances

Why: Makes it easier to identify resources, track costs, and manage your infrastructure at scale.

Example: Tags like Name=WebServer, Environment=Production, Project=Website help organize resources.

Real-World Scenarios

Scenario 1: Best-Case (Startup Web Application)

Context: A startup needs to launch their first web application with minimal cost.

Action: They launched a t3.micro instance (free tier eligible) with proper security groups, deployed their app, and configured auto-scaling for future growth.

Outcome: Application runs smoothly, costs remain under $10/month, and infrastructure can scale when user base grows.

Key Lesson: Start small with t3.micro, use free tier benefits, and plan for scaling from the beginning.

Scenario 2: Worst-Case (Security Misconfiguration)

Context: A developer launched an EC2 instance to test a new application.

Action: They opened all ports (0.0.0.0/0) in the security group for "easy access" during testing.

Outcome: Instance was compromised within hours, used for cryptocurrency mining, resulting in $3,000 unexpected bill.

Root Cause: Security group allowed unrestricted access from anywhere.

Resolution: Terminate compromised instance, create new one with restrictive security groups (only allow specific IPs and ports).

Key Lesson: NEVER open all ports to 0.0.0.0/0. Always use principle of least privilege.

❌ Common Mistake: Setting security group inbound rule to 0.0.0.0/0 for SSH (port 22)

Impact: Exposes instance to brute force attacks and unauthorized access from anywhere in the world.

Solution: Only allow SSH from your IP address or use AWS Systems Manager Session Manager for secure access.

Scenario 3: Edge Case (Sudden Traffic Spike)

Context: E-commerce site runs on single m5.large instance, handling 1,000 users/day normally.

Action: Black Friday sale causes traffic to spike to 50,000 concurrent users.

Outcome: Single instance couldn't handle load, website crashed, losing thousands in sales.

Explanation: No load balancing or auto-scaling configured to handle traffic spikes.

Solution: Implement Auto Scaling Group with multiple instances behind Application Load Balancer.

Key Lesson: Always plan for traffic spikes and implement auto-scaling for production workloads.

Interview Questions

🟢 Basic Level (Definitions & Core Concepts)

1 / 5

Question 1

What does EC2 stand for and what is its primary purpose?

Answer

EC2 stands for Elastic Compute Cloud. It provides scalable, resizable virtual servers (instances) in the AWS cloud, allowing you to run applications without maintaining physical hardware.

Question 2

What is the difference between stopping and terminating an EC2 instance?

Answer

Stopping an instance shuts it down but preserves the data on attached EBS volumes, and you can restart it later. Terminating an instance permanently deletes it and all data on instance store volumes (EBS volumes may be preserved based on DeleteOnTermination setting).

Question 3

What is an AMI in AWS EC2?

Answer

An AMI (Amazon Machine Image) is a template that contains the software configuration (operating system, application server, applications) required to launch an EC2 instance. It's like a snapshot or blueprint for creating instances.

Question 4

What are Security Groups in EC2?

Answer

Security Groups act as virtual firewalls for EC2 instances, controlling inbound and outbound traffic. They operate at the instance level and use allow rules only (no deny rules). All inbound traffic is blocked by default.

Question 5

What is the EC2 instance lifecycle?

Answer

The lifecycle includes: Pending → Running → Stopping → Stopped → Terminating → Terminated. You're only charged when the instance is in the Running state.

🟠 Intermediate Level (Scenarios & Reasoning)

1 / 3

Question 1

When would you choose a t3 instance over an m5 instance?

Answer

Choose t3 for burstable workloads with variable CPU usage (web servers, development environments) as they're more cost-effective. Choose m5 for applications requiring consistent high CPU performance with balanced compute, memory, and networking resources.

Question 2

How would you troubleshoot an EC2 instance that fails status checks?

Answer

First, identify which check failed (system or instance). For system check failures, stop and start the instance to migrate to new hardware. For instance check failures, check OS configuration, verify correct AMI, check for kernel panic, or review CloudWatch logs for errors.

Question 3

What's the best practice for handling SSH keys for EC2 access?

Answer

Store private keys securely (encrypted, never in version control), use different key pairs for different environments, rotate keys periodically, use IAM roles instead where possible, and consider AWS Systems Manager Session Manager for keyless access to instances.

Question 1:

Which EC2 instance type is best suited for a memory-intensive database application?

Correct Answer: C) r5.xlarge - Memory optimized instance

Explanation: The r5 family is specifically designed for memory-intensive applications like databases, with high memory-to-vCPU ratios. Option A (t3.micro) is too small and for burstable workloads. Option B (c5) is optimized for compute, not memory. Option D (m5) is balanced but not optimized for memory-intensive workloads like r5.

Question 2:

What happens to the data on an instance store volume when you stop an EC2 instance?

Correct Answer: B) The data is lost permanently

Explanation: Instance store volumes provide temporary block-level storage that is physically attached to the host computer. When you stop or terminate an instance, all data on instance store volumes is lost. This is why instance stores are called "ephemeral" storage. For persistent data, use EBS (Elastic Block Store) volumes instead.

Question 3:

Which of the following is the MOST secure way to allow SSH access to your EC2 instance?

Correct Answer: A) Allow SSH (port 22) only from your specific IP address

Explanation: Following the principle of least privilege, you should only allow SSH access from known, trusted IP addresses. Option B (0.0.0.0/0) exposes your instance to brute force attacks from anywhere on the internet. Option C is even worse, allowing all traffic. Option D completely removes security controls. Best practice: restrict SSH to your IP or use AWS Systems Manager Session Manager for keyless access.

Question 4:

You launched an EC2 instance but cannot connect to it via SSH. What should you check FIRST?

Correct Answer: D) All of the above

Explanation: All three factors are critical for SSH connectivity. You need: (A) A public IP to reach the instance from the internet, (B) Security group rules allowing SSH (port 22) from your IP, and (C) The correct private key matching the key pair specified when launching the instance. Missing any of these will prevent SSH connection. Always check all three systematically when troubleshooting.

Question 5:

What is the purpose of an EC2 key pair?

Correct Answer: C) To securely connect to EC2 instances via SSH or RDP

Explanation: EC2 key pairs consist of a public key (stored by AWS) and a private key (downloaded by you) used for secure authentication when connecting to instances. Linux instances use SSH with .pem keys, Windows instances use RDP with .ppk keys. Option A is wrong (that's KMS), Option B is wrong (that's VPN gateway), Option D is wrong (that's IAM access keys).
