🌐 Background: What Is a Checksum?

A checksum is like a unique seal on an envelope. An algorithm reads every single byte of your file in sequence and produces a fixed-length string. If even one byte changes — due to network packet corruption, hard drive failure, a cosmic ray, or any other reason — the checksum changes completely. This makes it impossible for corruption to go undetected.

Figure 2: One byte changed — completely different checksum. Corruption cannot hide.

Amazon S3 supports four additional checksum algorithms beyond its default MD5/ETag mechanism: SHA-1, SHA-256, CRC32, and CRC32-C. The checksum is calculated at upload time and preserved for the entire lifespan of the object, then validated again at download — providing true end-to-end data integrity.

Figure 3: Choosing the right algorithm — security vs. performance trade-off

Algorithm Output Speed Cryptographic Best For
SHA-256 256 bits Moderate ✅ Yes Healthcare, finance, compliance, archival
SHA-1 160 bits Moderate ⚠️ Weak Legacy compatibility only
CRC32 32 bits Fast ❌ No High-throughput media uploads
CRC32-C 32 bits Fastest ❌ No Large migrations, hardware-accelerated envs

✅ Key Rule: Regulated data → SHA-256. Maximum throughput → CRC32-C. Legacy systems → SHA-1. General media → CRC32.
