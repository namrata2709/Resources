🌟 Introduction

Imagine you are working on a remote Linux server — there is no desktop, no mouse, no fancy GUI text editor. You need to create a config file, fix a bug in a script, or search through thousands of log lines. What do you reach for? Command-line file editors and text-processing tools.

Figure 1: The Linux command-line toolkit covered in this session — editors and text processors

In this session we cover two families of tools:

  • File Editors — nano (beginner-friendly) and vi/vim (industry-standard, powerful)
  • Text Processing Commands — wc, grep, sort, and the all-important pipe| that chains them together

💡 Why does this matter for cloud/AWS work? When you SSH into an EC2 instance, you have no GUI. Everything you need to do — editing config files, searching logs, sorting output — is done with exactly these tools.

By the end of these notes you will be able to open, edit, save, and quit files using both nano and vi/vim, count and search file contents, sort data, and combine commands using pipes like a pro.

📝 What Are File Editors?

A file editor is a program that lets you create, view, and modify text files. Think of it as Notepad for the Linux terminal — except it works entirely through the keyboard, no mouse needed.

Figure 2: Notepad (Windows) vs command-line editors (Linux) — same job, different environment

On Windows, you use Notepad to edit .txt files. On Linux, you use command-line editors. These editors can only edit text files — just like Notepad cannot open a PDF, these editors work with plain text.

⚡ File editors in Linux are command-line tools used to create, view, and modify text files directly in the terminal without a graphical interface.

Types of Command-Line Editors

There are two main command-line editors you will use:

EditorBest ForDifficulty
nanoQuick edits, beginners⭐ Easy

📚 Note: Linux is case-sensitive. Always type commands in lowercase — nano not Nano, vi not VI.

🔵 Nano Editor

Nano is the beginner-friendly editor. If you've just started learning Linux and need to quickly create or edit a file, nano is your best friend. It shows you the available commands right at the bottom of the screen — no memorization needed.

Figure 3: Nano editor interface — menu options are always visible at the bottom

Opening and Creating Files with Nano

The syntax is simple:

nano filename.txt

If the file does not exist, nano will automatically create it and open it for editing. If the file already exists, nano simply opens it for editing. You don't need to create the file first — one command does both jobs.

✅ Nano Workflow:

  1. Type nano myfile.txt → file opens (created if new)
  2. Type or edit your content freely
  3. When done: press Ctrl + X to exit
  4. Nano asks "Save modified buffer?" → press Y
  5. Press Enter to confirm the filename

Key Shortcuts

Nano shows shortcuts at the bottom. The ^ symbol means Ctrl:

ShortcutAction
Ctrl + XExit nano (prompts to save if unsaved changes)
Ctrl + OSave (write out) without exiting
Ctrl + KCut current line
Ctrl + UPaste cut line
Ctrl + WSearch for text
Ctrl + GOpen help

💡 When saving, you can type Y or y — nano accepts both uppercase and lowercase.

Verifying Your Edit

After saving and exiting nano, verify the change with:

cat filename.txt

This prints the file contents so you can confirm your edits were saved correctly.

⚡ Vi / Vim Editor

If nano is a pocket knife, vi/vim is a Swiss Army sword. It is the most widely used text editor in the Linux/Unix world and is pre-installed on virtually every Linux system. AWS EC2 instances, Docker containers, embedded systems — vi is everywhere.

📚 vi stands for Visual Editor — it was the first screen-based text editor for Unix.vim stands for Vi IMproved — it has extra features like syntax highlighting and multi-level undo, but works identically for basic use.

Figure 4: Vi/Vim's three modes and how to switch between them — this is the key to mastering vi/vim

Understanding the Three Modes

The biggest concept in vi/vim is that it has three distinct modes, and understanding them is the key to mastering the editor.

ModeDescriptionHow to EnterHow to Exit
Command ModeDefault mode — navigate, delete, copy, saveOn start / press Esc—
Insert ModeType and edit textPress i, a, or oPress Esc
Last Line Mode (Ex Mode)Run commands: save, quit, searchPress : in Command ModePress Esc

⚡ When you first open a file with vi, you are in Command Mode by default — you cannot type text yet. You must switch to Insert Mode first.

Opening a File with Vi

vi filename.txt

Like nano, if the file doesn't exist it will be created. If it exists, it opens for editing — but you land in Command Mode, not Insert Mode.

Insert Mode — Typing Text

From Command Mode, press i to enter Insert Mode. You will see -- INSERT -- at the bottom of the screen, confirming you are in Insert Mode. Now you can type freely.

Figure 5: The INSERT indicator at the bottom confirms you are in Insert Mode and can type text

There are three ways to enter Insert Mode, each starting at a slightly different cursor position:

KeyInsert Mode Entry Point
iBefore the cursor
aAfter the cursor (append)
oOn a new line below the cursor

Command Mode — Navigation

Once you press Esc to return to Command Mode, you can navigate the file using the keyboard. This is where vi's power comes from — you can move, delete, copy, and jump around without touching a mouse:

KeyAction
hMove left
lMove right
jMove down
kMove up
0Go to beginning of line
$Go to end of line
ggGo to start of file
GGo to end of file
:nGo to line number n (e.g., :10)

💡 Memory trick: Think of hjkl as a tiny arrow keypad on your right hand — h (left), l (right), j (down), k (up). Many vi users never touch the arrow keys.

Last Line Mode — Save and Quit

To save or quit, press : from Command Mode to enter Last Line Mode. You will see a colon appear at the bottom of the screen. Now type your command:

CommandAction
:wSave (write) the file
:qQuit vi
:wqSave and quit
:xSave and quit (same as :wq)
:q!Quit without saving (force quit)

⚡ To save and exit vi/vim in one step, use :wq — this is one of the most commonly asked interview and exam questions about vi.

❌ Common mistake: Trying to type text while in Command Mode. If you open vi and start typing, nothing happens (or worse, you accidentally trigger navigation/deletion commands). Always check the bottom of the screen — if you don't see -- INSERT --, press i first.

The Full Vi Workflow

Figure 6: The complete vi workflow from open to save — follow these four steps every time

  1. Open file: vi filename.txt → lands in Command Mode
  2. Press i → enters Insert Mode → type your content
  3. Press Esc → returns to Command Mode
  4. Type :wq → save and quit

🔢 wc — Word Count

The wc command stands for word count. Think of it as the Linux equivalent of "word count" in Microsoft Word — but it also counts lines and characters. It is incredibly useful for quickly understanding the size and content of a file.

Figure 8: Understanding wc output — three numbers in order: lines, words, characters

Basic Usage

wc filename.txt

The output looks like this:

10 50 300 filename.txt

The three numbers in wc output represent, in order: lines, words, and characters (bytes).

Useful Options

CommandWhat it counts
wc filename.txtLines, words, and characters together
wc -l filename.txtLines only
wc -w filename.txtWords only
wc -c filename.txtCharacters (bytes) only

💡 Real-world use: Run wc -l /var/log/syslog to quickly see how many log entries your system has generated. When a log file grows to millions of lines, wc -l tells you in a fraction of a second.

🔍 grep — Search Inside Files

grep stands for Global Regular Expression Print. In simple terms: it is a search command. You give it a word (or pattern) and a file, and it finds every line containing that word. Imagine using Ctrl+F inside a document — but for the terminal, and a thousand times more powerful.

Figure 9: How grep works — scans every line and returns only those matching the pattern

Basic Usage

grep "error" /var/log/syslog

This prints every line in the file that contains the word "error". By default, grep is case-sensitive — searching for "error" will not match "Error" or "ERROR".

Useful grep Options

CommandWhat it does
grep "error" file.txtSearch for "error" (case-sensitive)
grep -i "error" file.txtCase-insensitive search (matches error, Error, ERROR)
grep -n "error" file.txtShow line numbers with results
grep -r "TODO" ~/projectsRecursively search all files in a directory
grep -v "error" file.txtShow lines that do NOT contain the pattern

⚡ Use grep -i to ignore case sensitivity — it matches all variations of the search term regardless of upper or lowercase letters.

⚡ Use grep -r to recursively search through all files inside a directory and its subdirectories.

💡 Real-world use: On an EC2 instance, run grep -i "error" /var/log/syslog to find all error messages regardless of how they were capitalized. Add -n to see the exact line numbers for easier debugging.

🔤 sort — Sort Lines in a File

The sort command does exactly what it sounds like — it sorts the lines of a file. You can sort alphabetically, numerically, in reverse order, or remove duplicate lines. Useful for organizing log files, lists of names, or any data where order matters.

Figure 10: sort command rearranges lines — default is alphabetical (A to Z)

Sort Options

CommandBehavior
sort filename.txtAlphabetical sort (A → Z) by default
sort -r filename.txtReverse alphabetical sort (Z → A)
sort -n filename.txtNumeric sort (0 → 9)
sort -nr filename.txtNumeric sort in reverse order (9 → 0)
sort -u filename.txtSort and remove duplicate lines
sort file.txt -o sorted.txtWrite sorted output to a new file

⚡ sort does not modify the original file — it only displays the sorted output on screen unless you redirect it with -o.

📚 According to Linux documentation, sort -u is equivalent to running sort followed by uniq — the -u flag removes consecutive duplicate lines after sorting.
📚 Source:Linux man page: sort

❌ Common mistake: Expecting sort to change the file. It doesn't. Use sort file.txt -o file.txt to overwrite the original, or sort file.txt -o sorted.txt to create a new sorted copy.

🔗 Pipe — Combining Commands

The pipe is represented by the | character — a straight vertical line on your keyboard (usually Shift + \). It is one of the most fundamental and powerful concepts in Linux. Pipe takes the output of one command and feeds it directly as the input to the next command.

Figure 11: Pipe chains commands together — each command's output becomes the next command's input

Syntax

command1 | command2 | command3

Linux executes this left to right:

  1. command1 runs and produces output
  2. That output is handed to command2 as input — command2 processes it and produces new output
  3. That new output is handed to command3, and so on
  4. The final output appears on your screen

Practical Examples

Figure 12: Three real pipe examples showing how commands chain together to produce powerful results

CommandWhat it does
ls -l | grep ".txt"List files, then filter to show only .txt files
cat /var/log/syslog | grep "error" | wc -lCount how many error lines are in the log
cat fruits.txt | sortDisplay fruits.txt content in sorted order
ps aux | grep "nginx"List all running processes, filter for nginx

⚡ Pipe is a fundamental Linux concept — it is commonly asked in interviews to test whether you understand how commands can be combined to solve complex problems with simple building blocks.

💡 Real-world use on AWS: On an EC2 instance, you might run:
grep "ERROR" /var/log/app.log | sort | uniq -c | sort -rn
This finds all error lines, sorts them, counts duplicates, and shows the most frequent errors first — all in one line.

📝 Overall Summary

  • File editors are command-line programs to create, view, and modify text files — the Linux equivalent of Notepad.
  • nano is the beginner-friendly editor — shows shortcuts at the bottom, use Ctrl+X → Y → Enter to save and exit.
  • vi/vim is the professional-grade editor — vi stands for Visual Editor, vim is Vi IMproved.
  • vi/vim has three modes: Command Mode (default), Insert Mode (press i to enter, Esc to exit), and Last Line Mode (press : from Command Mode).
  • To save and quit vi/vim: :wq. To quit without saving: :q!.
  • wc counts lines (-l), words (-w), and characters (-c) in a file.
  • grep searches for patterns inside files — use -i for case-insensitive, -n for line numbers, -r for recursive directory search.
  • sort sorts file lines alphabetically (default), numerically (-n), in reverse (-r), or removes duplicates (-u). It does not modify the original file.
  • Pipe (|) chains commands together — the output of one command becomes the input of the next.
  • All commands are case-sensitive — always use lowercase.

Project 7: Log Analysis CLI Tool — Job-Level Project

🎯 Objective: Build a reusable shell script that automates the entire log analysis workflow. This is a portfolio-worthy project.

⏱️ Time: 30-40 min

💰 Cost: Free

You've been running individual commands manually. Now you'll package them into a script that can be run with one command and produces a clean, formatted report.

The target output

When you run ./analyze.sh server.log, you should see:

========================================
       LOG ANALYSIS REPORT
========================================
File        : server.log
Total Logs  : 15
Total Errors: 7

--- Top Errors ---
      3 DB_TIMEOUT
      3 API_FAIL
      1 MEMORY_ERROR
========================================

Steps

  1. Create the script file: nano analyze.sh

  2. Type the following script exactly:

    #!/bin/bash

# Log Analysis Script
# Usage: ./analyze.sh filename

FILE=$1

echo "========================================"
echo "       LOG ANALYSIS REPORT"
echo "========================================"
echo "File        : $FILE"
echo "Total Logs  : $(wc -l < $FILE)"
echo "Total Errors: $(grep "ERROR" $FILE | wc -l)"
echo ""
echo "--- Top Errors ---"
grep "ERROR" $FILE | sort | uniq -c | sort -rn
echo "========================================"

    Save and exit: Ctrl + X → Y → Enter

    📸 Screenshot: analyze.sh script visible in nano — review before saving

  3. Make the script executable: chmod +x analyze.sh

  4. Run the script on your server.log: ./analyze.sh server.log

    📸 Screenshot: analyze.sh output — clean formatted log report generated in one command

  5. Test it on app.log too: ./analyze.sh app.log

  6. Extend it (bonus): Open analyze.sh with vi and add a line that also counts WARNING entries:

    echo "Total Warnings: $(grep "WARNING" $FILE | wc -l)"

✅ What you just built: A reusable DevOps tool that uses grep, wc, sort, and pipe together. This is the kind of automation that saves hours of manual log checking. Add this to your GitHub portfolio.

💡 Real-world connection: This is a simplified version of what tools like AWS CloudWatch Logs Insights, Splunk, and ELK Stack do — they automate exactly this pattern of filtering, counting, and ranking log data.
