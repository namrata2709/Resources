📘 Introduction

Before we dive into AWS, we need to answer a simple question: why does cloud computing even exist?

The answer starts with a very old problem — running your own servers is painful, expensive, and slow to scale. This section builds your mental model from the ground up: how servers work, what traditional IT looked like, and why the cloud became the dominant way to build technology.

By the end of this section, you will understand not just what cloud computing is, but why it works the way it does — and that understanding will make every AWS service you learn later feel logical rather than arbitrary.

Figure 1: Traditional IT vs Cloud Computing — the core shift this section explains

💡 Exam Context: This topic maps to Domain 1: Cloud Concepts of the CLF-C02 exam, which carries 24% of scored content. Questions will test your ability to explain cloud benefits, deployment models, service types, and the Shared Responsibility Model.

🖥️ How It All Started — Traditional IT

How Websites Work

Let's start at the very beginning. When you open a website, your browser (the client) sends a request across a network to a server — a computer sitting somewhere that holds the website's data. The server processes your request and sends a response back.

Think of it like sending a letter. You write a letter (your request), drop it in the mailbox, the post office network routes it to the right address (the server), and the recipient writes back (the response). The address on the envelope is like an IP address — it tells the network exactly where to deliver the data.

Figure 2: Client-Server communication — every website interaction follows this pattern

What Is Inside a Server?

A server is essentially a very powerful computer with four key components:

  • CPU (Compute) — The brain. Does calculations and processes your logic. Think of it as the part that actually "thinks."
  • RAM (Memory) — Very fast, short-term memory. When your app is running, data lives here for instant access.
  • Storage — Long-term data. Files, databases, logs — anything that needs to survive after the server reboots.
  • Networking — The server's connection to the outside world. Includes physical network cards, IP configuration, and routing.
💡 Why does this matter? Every AWS service you'll learn maps to one of these four pillars. EC2 = Compute. S3 = Storage. RDS = Database (structured storage). VPC = Networking. Understanding servers helps you understand why AWS is organized the way it is.

Key Networking Terms

Three terms come up constantly in cloud networking:

  • Network — A collection of cables, routers, and servers connected to each other. The internet is one massive network.
  • Router — Directs data packets between networks. Like a postal sorting hub — it decides which path your data takes to reach its destination.
  • Switch — Delivers packets to the correct device within a local network. Once data arrives at the right building (router), the switch gets it to the right desk (device).

The Traditional IT Problem

In the early days, companies literally bought physical servers and kept them in their offices. Google famously started in a garage. As demand grew, you needed more servers. More servers meant more space, more power, more cooling, more people to manage them.

This approach worked for years — but it had serious, expensive problems:

Figure 3: The six key problems with traditional on-premises IT infrastructure

ProblemReal-World Impact
Rent, power, coolingHigh fixed costs even when servers sit idle
Slow to scale upNeed to order, deliver, rack, and configure new servers — takes weeks
Scaling down is wastefulYou bought servers for peak demand — they sit idle during off-peak
Need 24/7 IT teamSomeone always has to be watching for failures
Disaster riskOne fire, flood, or power outage could take down your entire business
Limited agilityCan't experiment cheaply — buying a server to test an idea is expensive

The question became: can we outsource all of this to someone else? The answer is the cloud.

☁️ What Is Cloud Computing?

Cloud computing is the on-demand delivery of compute power, database storage, applications, and other IT resources through a cloud service platform with pay-as-you-go pricing.

Let's unpack that definition word by word:

  • On-demand — You get resources when you need them. No advance ordering, no waiting.
  • Pay-as-you-go — You pay only while you're using it. Stop using it, stop paying. Like electricity — you don't pay for the electricity you didn't use.
  • IT resources — Servers, storage, databases, networking, machine learning, analytics — everything a traditional data center would have.
⚡ The key shift: You don't own the hardware. AWS owns and maintains all the physical infrastructure. You simply use what you need, when you need it, through a web interface or API — and pay only for actual usage.

Figure 4: Breaking down the cloud computing definition into its three key ideas

You Already Use the Cloud

Cloud computing isn't abstract — you've been using it without realising. Gmail stores your email in the cloud. Google Drive and Dropbox store your files in the cloud. Netflix streams video entirely from AWS. Even Dropbox itself was originally built on AWS before building its own infrastructure.

These services share the same core trait: you don't manage the servers — someone else does — and you pay (or the company pays) only for what's used.

The US National Institute of Standards and Technology (NIST) defines cloud computing through five essential characteristics that every exam candidate should know:

🧱 Cloud Service Models — IaaS, PaaS, SaaS

Cloud computing isn't just one thing — it comes in different "levels" of abstraction. The higher the level, the less you manage. Understanding these three models is critical for the CLF-C02 exam because AWS offers services across all three.

Figure 8: The responsibility stack across On-Premises, IaaS, PaaS, and SaaS — orange = you manage, blue = AWS manages

IaaS — Infrastructure as a Service

IaaS provides the raw building blocks of cloud IT — networking, compute, and storage — in their most flexible form. You get the virtual servers and networking infrastructure, but you install the OS, configure the runtime, deploy your app.

Think of IaaS like renting a plot of land. AWS gives you the land (hardware), but you design and build the house (software).

  • AWS Example: Amazon EC2 — you get a virtual machine, you choose the OS and install whatever you want
  • Other providers: Microsoft Azure VMs, Google Compute Engine, DigitalOcean, Linode
  • Best for: Maximum flexibility; teams that need full control over their environment

PaaS — Platform as a Service

PaaS removes the need to manage underlying infrastructure — you focus only on deploying and managing your applications and data. AWS handles the OS, runtime, patching, and scaling. You just push your code.

PaaS is like renting a fully furnished apartment. The building is maintained for you — you just move in and live in it.

  • AWS Example: AWS Elastic Beanstalk — deploy your application, AWS handles the rest
  • Other providers: Heroku, Google App Engine, Windows Azure
  • Best for: Developers who want to ship code without worrying about infrastructure

SaaS — Software as a Service

SaaS is a complete, ready-to-use product run and managed entirely by the service provider. You use the software; you manage nothing underneath.

SaaS is like staying in a hotel. Everything is provided. You just show up and use it.

  • AWS Example: Amazon Rekognition (machine learning as a service — you call an API, you don't manage models or servers)
  • Everyday examples: Gmail, Dropbox, Zoom, Salesforce, Microsoft 365
  • Best for: End users who need software without IT overhead

Figure 9: IaaS vs PaaS vs SaaS — analogies, AWS examples, and use cases

⚡ Exam Tip: A question asking "which model requires the customer to manage the operating system?" → answer is IaaS (and On-Premises). PaaS and SaaS abstract the OS away.

AWS Pricing Fundamentals

Regardless of service model, AWS follows a consistent pay-as-you-go pricing model built on three dimensions:

Pricing DimensionWhat You Pay ForFree?
ComputeExact compute time used (per second or per hour)No — billed while running
StorageExact amount of data stored (per GB per month)No — billed for stored data
Data transfer OUTData leaving the cloud to the internetData IN is always free
💡 Remember: Data transfer into AWS is always free. Data transfer out of AWS to the internet is charged. This is a favourite exam trick — "ingress is free, egress is paid."

🌍 AWS Cloud Overview

Brief History of AWS

AWS didn't start as a cloud company — it grew out of Amazon's own need to manage massive IT infrastructure for its e-commerce business. Realising their internal infrastructure was a competitive strength, Amazon decided to offer it as a service to others.

YearMilestone
2002AWS launched internally at Amazon.com — IT departments could be externalized
2004First public offering: SQS (Simple Queue Service)
2006Relaunched with SQS + S3 + EC2 — the foundation of modern AWS
2007+Expanded globally beyond the US
TodayGlobal leader with hundreds of services across all major industries

AWS Today — By the Numbers

AWS is not just the first major cloud provider — it remains the dominant one. These numbers give context to why learning AWS is a career-defining skill:

  • AWS holds approximately 30% of the global cloud infrastructure market as of 2026, ahead of Microsoft Azure (~20%) and Google Cloud (~13%)
  • AWS revenue reached $107.5 billion in 2024, growing 19% year over year
  • AWS revenue grew 28% to $37.6 billion in Q1 2026 — its fastest growth in 15 quarters, driven largely by AI infrastructure demand
  • AWS has been the Gartner Magic Quadrant leader for cloud infrastructure for over 13 consecutive years
  • Customers include Netflix, Airbnb, McDonald's, NASA, Activision, 21st Century Fox, and millions of startups
💡 Note for CLF-C02: The exam may reference older figures (e.g., "31% market share" or "$90B revenue"). These numbers shift quarterly — understand the trend rather than memorising a specific figure. AWS is still #1, and that's the exam-testable fact.

What Can You Build on AWS?

AWS is used across virtually every industry. Common use cases include:

  • Enterprise IT migration (moving on-premises workloads to the cloud)
  • Backup and disaster recovery
  • Big data analytics and data lakes
  • Web and mobile application hosting
  • AI and machine learning model training and inference
  • Game server hosting
  • IoT device management
✅ Key Point: There is no single "type" of company that uses AWS. The cloud is industry-agnostic — if you have a compute, storage, or networking need, AWS has a service for it.

🗺️ AWS Global Infrastructure

AWS's global infrastructure is one of its biggest competitive advantages — and a major exam topic. Understanding how Regions, Availability Zones, and Edge Locations relate to each other is essential.

Figure 10: AWS Global Infrastructure — Regions contain Availability Zones, Edge Locations serve end users

AWS Regions

An AWS Region is a physical geographic location in the world that contains a cluster of AWS data centers. Each region is independent — data stored in one region does not automatically replicate to another.

Regions have name codes like us-east-1 (Northern Virginia), eu-west-1 (Ireland), ap-southeast-2 (Sydney). When you use an AWS service, you're using it in a specific region.

⚡ Critical Exam Concept: Most AWS services are region-scoped — using a service in one region is completely separate from using it in another region. If you create an EC2 instance in us-east-1, you won't see it from eu-west-1.

How to Choose an AWS Region

This is directly tested in CLF-C02. Four factors influence region selection — remember the acronym CLAP:

FactorWhat It MeansExample
ComplianceLegal requirements may mandate data stays in a specific countryFrench user data may legally need to stay in the Paris region
LatencyDeploy close to your users for faster response timesUS users → deploy in us-east-1, not ap-southeast-2
Availability (of services)Not all services exist in every regionCheck the AWS Regional Services page before deploying
PricingPrices vary by region — same service, different costus-east-1 is often cheapest; São Paulo is more expensive
💡 Priority Order: Compliance comes first — if law says data must stay in a country, that overrides all other factors. Then latency. Then service availability. Then pricing.

Availability Zones (AZs)

Each AWS Region contains multiple Availability Zones (AZs) — isolated data center facilities within the same region, connected by high-bandwidth, ultra-low latency private networking.

Key facts about AZs:

  • Each region has a minimum of 3 AZs and a maximum of 6 AZs. The usual number is 3.
  • Each AZ is one or more discrete data centers — AWS doesn't publish exactly how many
  • AZs are physically separated from each other so that a disaster (fire, flood, power outage) in one AZ does not affect others.
  • They are connected with high-speed private links — so replicating data between AZs is fast

Example: The Sydney region (ap-southeast-2) has three AZs: ap-southeast-2a, ap-southeast-2b, ap-southeast-2c.

✅ Why AZs Matter: Deploying your application across multiple AZs means if one data center goes down, your app keeps running in the others. This is the foundation of high availability on AWS.

Points of Presence / Edge Locations

AWS has over 400+ Points of Presence (Edge Locations) across 90+ cities in 40+ countries. These are not full Regions — they are smaller nodes that cache content closer to end users.

Edge Locations are used by services like Amazon CloudFront (AWS's CDN) to deliver content with the lowest possible latency. When a user in Mumbai requests a video, CloudFront serves it from the nearest Edge Location rather than routing all the way to a distant region.

💡 Remember the hierarchy: Region → Availability Zones → Data Centers. Edge Locations are separate — they exist outside Regions to serve content closer to users.

Global vs. Regional Services

Most AWS services are regional — you create them in a specific region. But some are truly global and don't require a region selection:

TypeExamplesWhat "Global" Means
Global ServicesIAM, Route 53, CloudFront, WAFThe same configuration applies worldwide — no region selection needed
Regional ServicesEC2, Elastic Beanstalk, Lambda, RDSCreated and managed within a specific region
⚡ Exam Tip: IAM (Identity and Access Management) is one of the most commonly tested global services. IAM users, groups, roles, and policies are global — not region-specific.

🔐 The Shared Responsibility Model

This is one of the most important concepts in the entire CLF-C02 exam — and it comes up in almost every AWS security question. The Shared Responsibility Model defines exactly who is responsible for what when using AWS.

Figure 11: The AWS Shared Responsibility Model — the most important security concept for CLF-C02

AWS Responsibility — "Security OF the Cloud"

AWS is responsible for the security of the cloud — the physical hardware, data centers, networking, and the foundational services that underlie everything.

AWS is responsible for:

  • Physical security of data centers (access controls, cameras, guards)
  • Hardware (servers, storage devices, networking equipment)
  • The underlying virtualization layer (hypervisors)
  • Global infrastructure: Regions, Availability Zones, Edge Locations
  • Managed service infrastructure (for services like RDS, the database engine patching is AWS's job)

Customer Responsibility — "Security IN the Cloud"

The customer is responsible for the security in the cloud — everything they configure, deploy, and operate within the AWS environment.

Customers are responsible for:

  • Their data (encryption at rest and in transit)
  • Identity and access management (who can access what in their AWS account)
  • Operating system configuration and patching (on EC2 instances)
  • Network and firewall configuration (Security Groups, NACLs)
  • Application-level security
  • Client-side data encryption

Shared Responsibility Varies by Service Type

The exact boundary shifts depending on which type of service you use:

Service TypeCustomer ManagesAWS Manages
IaaS (e.g., EC2)OS, runtime, app, data, security configurationHypervisor, physical hardware, data center
PaaS (e.g., Elastic Beanstalk, RDS)Application code, data, access controlOS patching, runtime, scaling infrastructure
SaaS (e.g., Rekognition)Data sent in, access permissionsEverything else — the service itself
⚡ Memory Trick:
"Security OF the cloud" → AWS
"Security IN the cloud" → Customer
The preposition tells you who owns it.
❌ Common Exam Mistake: Students often say AWS is responsible for OS patching. That's only true for managed services like RDS. For EC2 (IaaS), YOU patch the OS. AWS only patches the hypervisor underneath.

📋 AWS Acceptable Use Policy

When you create an AWS account, you agree to the AWS Acceptable Use Policy. The policy is straightforward common sense, but it's worth knowing for the exam.

AWS prohibits:

  • Illegal, harmful, or offensive use or content
  • Security violations (hacking, unauthorized access, port scanning)
  • Network abuse (DDoS attacks, flooding)
  • Email or messaging abuse (spam, phishing)
💡 Exam Note: The CLF-C02 doesn't test specific policy wording, but you should know the policy exists and understand that using AWS for illegal activities is prohibited by contract.

🎯 Key Takeaways

Before moving on, make sure you can answer these questions confidently:

  • Why did the cloud emerge? — Traditional IT was too expensive, slow to scale, and risky for single-location businesses
  • What is cloud computing in one sentence? — On-demand delivery of IT resources over the internet with pay-as-you-go pricing
  • What are the three deployment models? — Private, Public, Hybrid. Know when to use each.
  • What are IaaS, PaaS, SaaS? — Progressively less management for the customer. EC2 = IaaS. Elastic Beanstalk = PaaS. Gmail = SaaS.
  • What are AWS Regions and AZs? — Regions are geographic clusters of data centers. AZs are isolated facilities within a region (min 3, max 6 per region).
  • What is the Shared Responsibility Model? — AWS = security OF the cloud (hardware, physical). Customer = security IN the cloud (data, config, OS on EC2).
⚡ Most Common Exam Question Pattern for This Topic: "Which of the following is the customer's responsibility under the Shared Responsibility Model?" → Anything about their data, OS configuration, network settings, or access management.

📝 CLF-C02 Exam Tips

These are the highest-priority things to know from this entire section for your CLF-C02 exam:

  1. Cloud computing is defined by on-demand delivery + pay-as-you-go pricing — both terms matter.
  2. Know all three deployment models and when to use hybrid (company has compliance requirements but wants cloud flexibility).
  3. Know the difference between IaaS, PaaS, SaaS and which AWS services fall into which category (EC2 = IaaS, Beanstalk = PaaS, Rekognition = SaaS).
  4. AWS pricing: data IN is free, data OUT is charged.
  5. Know the four region selection factors — Compliance, Latency, Service Availability, Pricing.
  6. Each region has a minimum of 3 AZs and a maximum of 6 AZs.
  7. Global services: IAM, Route 53, CloudFront, WAF. Everything else is regional.
  8. Shared Responsibility: AWS = OF the cloud (physical). Customer = IN the cloud (config, data, OS on EC2).
  9. RDS database engine patching = AWS. EC2 OS patching = Customer.
  10. AWS has 400+ Points of Presence in 90+ cities across 40+ countries.

🤔 Reflection Questions

1. A startup is building a new application. They have very unpredictable traffic — slow on weekdays, massive spikes on weekends. Which cloud characteristic makes the cloud perfect for this scenario, and why?

💡 Hint

Think about the characteristic that allows resources to grow and shrink automatically based on demand — and how that saves money compared to buying servers for peak load.

2. A healthcare company needs to store patient records and is required by law to keep all data within their country. They also want to use the cloud for their non-sensitive marketing workloads. Which deployment model should they use, and why?

💡 Hint

One type of data must stay on-premises (or in a private cloud), while other workloads go to the public cloud. What model combines both?

3. Your company asks you: "Who is responsible for patching our database?" The answer depends on what service you use. Explain the difference between using EC2 to host MySQL vs using RDS.

💡 Hint

EC2 is IaaS — think about what the customer fully controls. RDS is a managed service — think about what AWS takes over in managed services.

4. Explain to a non-technical manager why the company should switch from buying their own servers (CAPEX) to AWS (OPEX). Use a real-world analogy.

💡 Hint

Think about the difference between buying a car (you own it, insure it, maintain it, it depreciates) vs taking an Uber (pay per trip, no maintenance).

5. You are deploying an application that must be available even if one AWS data center completely fails. What AWS infrastructure concept should you use, and why?

💡 Hint

Think about the isolated units within a region that are designed to be independent — so a failure in one doesn't cascade to others.
