🐧 What is Linux?

Imagine you are building a house. You need a foundation, walls, plumbing, electricity, and finally the furniture and appliances you use every day. An operating system (OS) is exactly this — it is the complete infrastructure that lets your applications (the furniture) run on top of hardware (the foundation).

Linux is a free, open-source operating system kernel created by Linus Torvalds in 1991, derived from Unix principles.

But here is the important distinction your instructor made in class:

⚡ Linux = Linux Kernel + GNU Utilities

The kernel alone is not a complete OS. GNU (GNU's Not Unix) provides all the tools — ls, cp, grep, mv and hundreds more — that make the system actually usable. Together, they form what we call "Linux."

Linux vs Unix — What's the Difference?

Unix was created at Bell Labs in the late 1960s. It was a revolutionary multi-user, multitasking operating system — but it was proprietary (paid). Linux was designed following Unix principles and philosophy but is an entirely independent, open-source implementation — not a copy of Unix source code.

Think of it like this: Unix invented the recipe. Linux created its own dish using the same cooking philosophy — but with free ingredients that anyone can use.

🏗️ Linux Architecture

Think of Linux architecture like the floors of a building — each floor serves a specific purpose, and you cannot reach the top without passing through the floors below. Let us walk through each layer, from the ground up.

Figure 3: Detailed Linux architecture — 5 layers from hardware to applications

Layer 1: Hardware

At the very bottom sits the physical machine — the CPU, RAM, storage disks, and network interfaces. This is what you are renting when you launch an EC2 instance. The hardware does not understand your commands directly. It needs an intermediary — the Kernel.

Layer 2: The Kernel

The Kernel is the core of Linux — it acts as the bridge between software applications and hardware, managing CPU, memory, I/O devices, and all system calls.

The Kernel's responsibilities:

  • Process Management: Decides which process runs on the CPU at any given moment (scheduling)
  • Memory Management: Allocates and deallocates RAM for running programs
  • Device Drivers: Translates generic software requests into hardware-specific instructions
  • System Calls: The API between user-space applications and kernel-space hardware
  • Security: Enforces file permissions and process isolation

💡 Kernel Panic: If the Linux Kernel crashes (called a "kernel panic"), the entire OS halts — similar to a heart attack. In AWS, this would make your EC2 instance unresponsive, requiring a stop/start to move to new hardware.

Layer 3: The Shell

The Shell is the interface between you and the Kernel. The Shell acts as a command interpreter — it takes commands typed by the user, interprets them, and passes execution requests to the Kernel.

Think of the Shell as the receptionist in an office. You tell the receptionist what you need. The receptionist (Shell) passes the request to the appropriate department (Kernel), which does the actual work and returns the result.

Layer 4: Bash — The Default Shell

Bash (Bourne Again SHell) is the default command-line interpreter on most Linux systems, including Amazon Linux EC2 instances.

When you SSH into an EC2 instance and type commands, you are in a Bash session. Bash also supports shell scripting — writing sequences of commands in a .sh file to automate repetitive tasks. (Note: Shell scripting will be covered later in this course.)

Figure 4: What happens when you type a command — the Bash to Kernel flow

Layer 5: File System

The Linux File System is a hierarchical structure starting from the root directory (/) — every file, directory, and device in Linux exists within this single tree.

Unlike Windows (where you have C:\, D:\, etc.), Linux has one unified tree rooted at /. Everything — files, hardware devices, network connections — is represented as a file in this hierarchy.

Layer 6: GNU Utilities and Applications

At the top of the stack sit the GNU utilities and user applications. GNU utilities provide the essential command-line tools — ls, cp, mv, grep, find — that make Linux usable beyond just the Kernel.

Applications (like Apache web server, MySQL database, Python scripts) sit at the very top, using GNU tools and making kernel system calls to do their work.

⭐ Why Linux is So Popular

Your instructor asked a great question in class: "Why is Linux so popular?" Let us go beyond the buzzwords and understand the real reasons — the ones that matter in an interview and in real-world architecture decisions.

Figure 6: Linux vs Windows — why Linux wins for server workloads

1. Free and Open-Source

Linux is free to use, modify, and distribute under the GNU General Public License (GPL) — there are no licensing fees.

Compare this to Windows Server, which can cost hundreds of dollars per core per year. For a company running thousands of EC2 instances, this difference is enormous. Amazon Linux 2 — AWS's own Linux distribution — is completely free to use on EC2.

2. Faster and Lightweight (Headless Architecture)

Most Linux servers run headless — without a graphical user interface. No GUI means no wasted RAM and CPU on rendering windows, animations, or visual effects. A Linux server dedicates nearly all resources to its actual workload — not to maintaining a desktop interface.

This is why your EC2 Linux instance can handle thousands of web requests with minimal CPU usage, while a Windows server of the same size uses significant resources just for the OS background processes.

3. Highly Secure — No Antivirus Needed

This was a key point in class: Linux does not require antivirus software because its permission model, user isolation, and process sandboxing limit the spread and impact of malware.

Four pillars of Linux security:

  • File Permissions: Every file has read/write/execute permissions for owner, group, and others
  • User Isolation: Each process runs as a specific user — a compromised process cannot affect other users' files
  • Root Separation: Root (superuser) access is not granted by default — escalation requires explicit authentication
  • Process Isolation: Processes cannot directly access another process's memory space

✅ AWS Security Note: While Linux itself is secure, you still need to configure AWS Security Groups, IAM roles, and network ACLs properly. OS security and cloud-level security work together.

4. Stability

Linux servers are famous for running for years without needing a reboot. In contrast, Windows servers require regular restarts for updates. For cloud workloads that need high availability, this stability is critical.

5. Massive Open-Source Ecosystem

Every major cloud tool — Docker, Kubernetes, Terraform, Ansible, Nginx, Apache, MySQL — is Linux-native. The ecosystem built around Linux is unmatched in the server world.

📦 Linux Distributions

The Linux Kernel is the engine. A distribution (or "distro") is the complete car — the kernel plus a pre-configured set of software, package manager, and sometimes a desktop environment.

A Linux distribution is a complete operating system that packages the Linux Kernel with GNU tools, a package manager, and additional pre-configured software.

🔌 Connecting to a Linux EC2 Instance

Now let us get practical. You have launched a Linux EC2 instance. How do you actually get into it and run commands? There are two primary methods — your instructor demonstrated both in class.

Figure 8: Choosing between SSH and EC2 Instance Connect for Linux EC2 access

Method 1: SSH Client (with Key Pair)

SSH (Secure Shell) is the standard protocol for remotely accessing Linux servers. SSH uses asymmetric cryptography — AWS stores the public key on the EC2 instance, and you keep the private key (.pem file) on your machine.

How it works:

  1. When launching EC2, you select or create a key pair. AWS places the public key on the instance.
  2. You download the .pem file (private key) — save it safely, you cannot download it again.
  3. Connect using: ssh -i /path/to/key.pem ec2-user@<public-ip>

📸 Screenshot: The Connect page on an EC2 instance — SSH client tab showing the full connection command

❌ Common Mistake: Using port 22 (SSH) open to 0.0.0.0/0 in your Security Group. This exposes your server to the entire internet. Always restrict SSH access to your specific IP address or company IP range.

Key pair types at a glance:

Key ComponentLocationWho Manages It
Public KeyOn the EC2 instanceAWS places it automatically
Private Key (.pem)Your local machineYou — keep it secret!

Method 2: EC2 Instance Connect

EC2 Instance Connect is an AWS-managed, browser-based SSH connection to Linux EC2 instances, available directly from the AWS Management Console — no external SSH client or permanent key pair required.

When to use EC2 Instance Connect:

  • You launched the instance without a key pair ("Proceed without a key pair")
  • You want a quick, browser-based terminal for one-off tasks
  • You don't have an SSH client installed on your machine
  • You want IAM-controlled access with CloudTrail audit logs

How it works (under the hood):

  1. You click "Connect" in the AWS console and select "EC2 Instance Connect"
  2. AWS generates a one-time temporary SSH public key (valid for 60 seconds for upload)
  3. AWS pushes the temporary key to the instance's authorized_keys
  4. A browser-based SSH session opens — you are connected as ec2-user

📸 Screenshot: EC2 Instance Connect tab in the AWS console — showing the username and Connect button

⚡ Critical Fact: EC2 Instance Connect is only available for Linux EC2 instances, not for Windows EC2 instances. For Windows EC2, you use RDP (Remote Desktop Protocol) on port 3389.

📝 Overall Summary

  • Linux is open-source: Free to use, modify, and distribute — built on the Linux Kernel + GNU utilities. Created by Linus Torvalds in 1991, derived from Unix principles.
  • Linux Architecture has 4 core layers: Hardware → Kernel → Shell → Applications. The Kernel bridges software and hardware; the Shell interprets user commands for the Kernel.
  • Bash is the default shell: On Amazon Linux EC2 instances, Bash is the command-line interpreter you interact with. It processes commands and delegates to the Kernel.
  • Linux File System starts at /: One unified hierarchical tree starting from root (/). Directories like /home, /etc, /var, /bin serve specific purposes.
  • Linux does not need antivirus: Its permission model, user isolation, and process sandboxing make it inherently secure — attack surfaces are far smaller than Windows.
  • SSH is the protocol for Linux EC2 access: Uses port 22, asymmetric key pairs. The default username on Amazon Linux is ec2-user.
  • EC2 Instance Connect is AWS's browser-based SSH: No external SSH client or key pair needed. Only available for Linux EC2 instances — not Windows (which uses RDP on port 3389).
  • AWS Canvas labs are temporary: All resources auto-delete when a session ends. Never confuse Canvas lab resources with your real AWS account.
  • Linux dominates servers: ~96% of web servers, all top 500 supercomputers, most cloud workloads run Linux — because it is free, lightweight, stable, and secure.
  • Course context: We are now in Module 2 (Linux). After ~5 sessions on Linux, we move to Networking → Security → EC2 Advanced (Auto Scaling, Load Balancer) → Storage.

Project 5: Backup Automation Script

🎯 Objective: Write a script that automatically backs up your notes app to a timestamped backup folder. You learn automation and scheduling — the foundation of DevOps.

⏱️ Time: 30–40 min

💰 Cost: Free (uses instance from Project 1)

  1. Create the backup destination directory:

    mkdir -p /home/ec2-user/backup/archives

  2. Create the backup script:

    nano /home/ec2-user/backup.sh

    Type the following content:

    #!/bin/bash

# ============================
# BACKUP AUTOMATION SCRIPT
# ============================

SOURCE="/home/ec2-user/notes-app"
DEST="/home/ec2-user/backup/archives"
TIMESTAMP=$(date +"%Y-%m-%d_%H-%M-%S")
BACKUP_NAME="notes-backup-$TIMESTAMP"

echo "Starting backup at $TIMESTAMP..."

# Create timestamped backup folder
mkdir -p "$DEST/$BACKUP_NAME"

# Copy all notes to backup
cp -r "$SOURCE/"* "$DEST/$BACKUP_NAME/"

🤔 Reflection Questions

1. If someone asks you "Is Linux just a terminal?", how would you explain what Linux actually is?

💡 Hint

Think about the components: Kernel, Shell, File System, GNU utilities. The terminal (shell) is just one layer of a multi-layered OS. Linux can also have a GUI — most servers just choose not to use one.

2. You are given a new Linux EC2 instance without a key pair. What are your connection options and which would you choose for a production server?

💡 Hint

EC2 Instance Connect works without a key pair. But for production, consider AWS Systems Manager Session Manager — no open port 22, fully audited. Think about the tradeoffs: convenience vs security.

3. Your manager asks why the company should pay for Linux hosting instead of using a free Linux server. What's wrong with this reasoning?

💡 Hint

The OS itself (Linux) is free. You pay for the EC2 compute resources (CPU, RAM, storage) — not the Linux license. This is different from Windows EC2, where you pay for both compute AND the Windows Server license.

4. A classmate says "I deleted my EC2 instance in the Canvas lab — I need to restore my work." What do you tell them?

💡 Hint

Canvas lab environments are temporary and sandboxed. Resources deleted inside a lab session cannot be recovered — the environment resets. They need to redo the work within the current session.

5. Explain to a non-technical friend what the "Kernel" does, using an analogy from everyday life.

💡 Hint

Think of the kernel as the manager of a factory floor. Workers (applications) give requests to their supervisor (Shell), who relays them to the factory manager (Kernel). The manager decides which machine (hardware) does what job, in what order, and for how long.

6. Why do companies like Netflix and Amazon run their backend servers on Linux rather than Windows? What specific advantages matter most at scale?

💡 Hint

Consider: licensing cost at thousands of servers, headless architecture freeing up resources, stability (uptime), ecosystem compatibility (Docker, Kubernetes, Nginx are Linux-native), and security model.
