🔐 SSH Access to User Accounts in Amazon Linux

SSH stands for Secure Shell. It is a protocol that allows you to securely connect to a remote server over the internet. When you launch an Amazon Linux EC2 instance, you connect to it using SSH — not by physically sitting in front of it.

Figure 2: SSH — your laptop securely connecting to a remote EC2 instance

SSH provides an encrypted channel between your local system and your EC2 instance, ensuring that all data transmitted — including your login credentials — is protected from eavesdropping.

Two Methods of SSH Login

There are two ways to log in to a Linux user account on Amazon Linux:

MethodHow It WorksIs It Safe?
Password-BasedEnter IP address + username + password❌ Less secure — anyone who knows your password can log in
SSH Key-BasedUse a private key on your laptop matched to a public key on the server✅ Highly secure — even if someone steals your password, they can't log in without the private key

💡 By default, Amazon Linux does not support password-based authentication. It supports only SSH key-based login. This is a security decision made by AWS to protect your instances from brute-force attacks.

How SSH Key Pairs Work

Think of SSH key pairs like a serial note from a movie — you have one half and the server has the other half. Only when both halves match does the door open.

In technical terms:

  • Private Key — Stored on your laptop. Never share this with anyone. It is like your house key.
  • Public Key — Stored on the remote server inside the user account's ~/.ssh/authorized_keys file. It is like the lock on the door.

When you attempt to connect, the server checks whether your private key matches the public key stored in authorized_keys. If they match, access is granted.

Figure 3: How the SSH key pair authentication flow works

✅ Where keys are stored:

  • Private key: ~/.ssh/id_rsa (on your local laptop)
  • Public key: ~/.ssh/id_rsa.pub (on your local laptop)
  • Public key on server: ~/.ssh/authorized_keys (inside the user account on the EC2 instance)

Method 1: Password-Based Authentication

Although not recommended, you can enable password-based login by editing the SSH configuration file on the server. Here is how the login works once enabled:

To connect via SSH with a password, you need three things: the public IP address of the server, the username of the account you want to log into, and the password for that account.

To enable password-based login, you must edit /etc/ssh/sshd_config and change PasswordAuthentication from no to yes, then restart the SSH service.

# Edit the SSH daemon configuration filesudo vim /etc/ssh/sshd_config# Find and change:# PasswordAuthentication no# to:# PasswordAuthentication yes# Restart the SSH service to apply changessudo systemctl restart sshd

❌ Why password login is risky: If anyone discovers your password, they can log in immediately. Password-based authentication is vulnerable to brute-force attacks. Always prefer key-based authentication.

Method 2: SSH Key-Based Authentication (Recommended)

This is the standard, secure method. There are three steps involved:

Step 1 — Generate SSH key pair on your local machine:

ssh-keygen -t rsa -b 4096 -C "[email protected]"

Breaking this command down:

  • ssh-keygen — the tool to generate SSH key pairs (both public and private keys)
  • -t rsa — specifies the RSA encryption algorithm for generating the keys
  • -b 4096 — sets the bit strength to 4096, which is stronger and more secure than the default 2048-bit
  • -C "[email protected]" — adds a comment or label to the key, typically your email ID, to help you identify the key if you have multiple key pairs

After running the command, press Enter at each prompt (or set a passphrase for extra security). Two files are created:

  • ~/.ssh/id_rsa — your private key (never share this)
  • ~/.ssh/id_rsa.pub — your public key (safe to copy to servers)

💡 Windows users: The default Windows command prompt does not support all Linux commands like ssh-copy-id. Install Git Bash (from git-scm.com) to run Linux commands on Windows. Once installed, launch Git Bash to execute the commands below.

Step 2 — Copy the public key to the server:

# Using ssh-copy-id (recommended — works in Git Bash or Linux/Mac terminal)ssh-copy-id -i ~/.ssh/id_rsa.pub username@public-ip-address# Example: copying public key to the 'vikram' user accountssh-copy-id -i ~/.ssh/id_rsa.pub [email protected]

This command automatically adds your public key to the ~/.ssh/authorized_keys file on the server. You will be asked for the user's password once during this step.

Alternatively, if ssh-copy-id is not available, you can do it manually:

# On the server, inside the target user accountmkdir -p ~/.sshnano ~/.ssh/authorized_keys# Paste the contents of your id_rsa.pub file here, save and exit

Step 3 — Connect using your private key:

# SSH into the EC2 user account (default)ssh -i ~/.ssh/id_rsa ec2-user@public-ip-address# SSH into a custom user account (e.g., vikram)ssh -i ~/.ssh/id_rsa vikram@public-ip-address

Figure 4: Three steps to set up and use SSH key-based authentication

Here are the most common issues you will encounter and how to fix them:

ErrorCauseFix

  • Are you using the correct username? (Default is ec2-user for Amazon Linux)

🔒 Linux File Permissions

Every file and folder in Linux has a set of permissions that controls who can do what with it. This is one of the most important security features of Linux — and it is heavily tested in interviews and exams.

Figure 5: Linux file permissions — three categories, three types each

The Three Permission Types

Every file or directory in Linux has three types of permissions:

PermissionSymbolFor FilesFor Directories
ReadrView the file's contentsList the files inside the directory
WritewEdit or modify the fileCreate or delete files inside the directory
ExecutexRun the file as a program or scriptEnter (cd into) the directory

💡 Real-world analogy: Imagine a notebook. Read means you can look at the notes. Write means you can add or erase notes. Execute means you can act on the instructions in the notebook — like actually cooking a recipe written there.

The Three Permission Categories

Permissions are assigned to three types of users:

  • Owner (u) — The user who created the file. They usually have the most permissions.
  • Group (g) — A group of users who share certain access. For example, a "developers" group might all have read access to source code files.
  • Others (o) — Everyone else on the system who is not the owner and not in the group.

Figure 6: Anatomy of a Linux permission string

Reading the Permission Output

When you run ls -l in Linux, each file shows a permission string like this:

drwxr-xr-x 2 vikram vikram 4096 Oct 27 10:00 vikram-rw-r--r-- 1 ec2-user ec2-user 123 Oct 27 10:00 myfile.txt

The first column (drwxr-xr-x) is the permission string. Here is how to read it:

PositionWhat It MeansExample Value
1st characterFile type: d = directory, - = regular file, l = symbolic linkd
Characters 2–4Owner permissions (rwx)rwx = read, write, execute
Characters 5–7Group permissions (rwx)r-x = read and execute only
Characters 8–10Others permissions (rwx)r-x = read and execute only

A - (dash) in a permission position means that permission is denied for that category. For example, rw- means read and write are allowed, but execute is denied.

Viewing File and Directory Permissions

Use these commands to check permissions:

# List all files with permissions in the current directoryls -l# List permissions of a specific filels -l filename.txt# Check permissions of a directory itself (not its contents)ls -ld /home/vikram# Check with absolute pathls -l /home/vikram

💡 Key difference:ls -l /home/vikram lists the contents of the vikram directory. ls -ld /home/vikram shows the permissions of the directory itself.

Real-World Demo: Why Permissions Matter

Here is a real scenario from the session that shows why permissions are so important:

# We are logged in as ec2-user# Try to enter the vikram directorycd /home/vikram# Output: -bash: cd: vikram: Permission denied# Even with sudo, it is deniedsudo cd /home/vikram# Output: sudo: cd: command not found (cd is a shell built-in, not external)# Switch to the vikram user firstsu - vikram# (enter password)# Now check vikram directory permissionsls -l# Output shows: drwx------ vikram vikram ... vikram# This means: owner (vikram) has rwx, but group and others have NOTHING

The drwx------ means only the owner (vikram) can read, write, or enter that directory. The EC2 user (a different user) gets permission denied — which is exactly how Linux keeps user accounts private and secure.

Figure 7: How file permissions block unauthorized access — even to other users on the same server

🛠️ Modifying File Permissions with chmod

chmod stands for change mode. It is the command used to change file or directory permissions in Linux. There are two ways to use chmod: the symbolic method (using letters) and the numeric/octal method (using numbers).

Symbolic Method

The symbolic method uses letters to add (+) or remove (-) or set (=) permissions for a specific category of users:

# Syntaxchmod [who][operation][permissions] filename# who: u = owner, g = group, o = others, a = all# operation: + add, - remove, = set exactly# permissions: r = read, w = write, x = execute

Examples from the session:

# Give all permissions (rwx) to others on the vikram directorychmod o+rwx vikram# Remove all permissions from otherschmod o-rwx vikram# Give read permission to the groupchmod g+r myfile.txt# Give execute permission to the ownerchmod u+x script.sh# Remove write permission from everyonechmod a-w important.txt

💡 Memory trick:u = user/owner, g = group, o = others, a = all. The + adds permissions, - removes them, = sets them exactly (replaces whatever was there).

Octal (Numeric) Method

In the numeric method, each permission is represented by a number. This method is faster once you remember the values:

PermissionNumeric Value
Read (r)4
Write (w)2
Execute (x)1
No permission (-)0

You add the numbers together for each category (owner, group, others):

CombinationValueMeaning
rwx4+2+1 = 7Full permissions
rw-4+2+0 = 6Read and write
r-x4+0+1 = 5Read and execute
r--4+0+0 = 4Read only
---0+0+0 = 0No permissions
# Give full permissions to owner, read+execute to group and otherschmod 755 myfile.sh# Give full permissions to owner, read+write to group, nothing to otherschmod 760 project/# Give read+write to owner only, nothing to everyone elsechmod 600 private-key.pem

chmod 755 means the owner has rwx (7), group has r-x (5), and others have r-x (5) — commonly used for scripts and directories.

Figure 8: chmod octal method — how numbers map to permissions

✅ Common chmod values to remember for exams and interviews:

  • chmod 777 — Full permissions for everyone (use only in testing, never in production)
  • chmod 755 — Owner full, group and others read+execute (standard for directories and scripts)
  • chmod 644 — Owner read+write, group and others read only (standard for files)
  • chmod 600 — Owner read+write only, nobody else (standard for private SSH keys)
  • chmod 400 — Owner read only (used by AWS for downloaded .pem key files)

Recursive Permission Changes

To apply permissions to a directory and all its contents at once, use the -R flag:

# Give owner full permissions on a directory and everything inside itchmod -R 700 /home/vikram# Give read access to everyone on a web folderchmod -R 755 /var/www/html

👤 Changing Ownership with chown and chgrp

Permissions control what someone can do. Ownership controls who the owner is. You can change file ownership using chown and group ownership using chgrp.

chown is used to change the owner of a file or directory, and only the root user (or sudo) can change ownership.

# Change owner of a file to 'vikram'sudo chown vikram myfile.txt# Change owner and group at the same timesudo chown vikram:developers myfile.txt# Change only the groupsudo chgrp developers myfile.txt# Recursive — change ownership for directory and all contentssudo chown -R ec2-user:ec2-user /home/project

💡 Checking current ownership: When you run ls -l, the 3rd column is the owner username and the 4th column is the group name. For example: -rw-r--r-- 1 vikram developers 1234 Oct 27 myfile.txt — here vikram is the owner and developers is the group.

Figure 9: chown and chgrp — changing who owns a file

🎯 Default File Permissions and umask

When you create a new file or directory in Linux, it does not get random permissions — it gets default permissions. These defaults are controlled by a value called umask (user file creation mask).

The umask value is subtracted from the maximum default permissions to determine the actual permissions assigned to newly created files and directories.

  • Maximum default for a file: 666 (rw-rw-rw-) — files do not get execute by default for security
  • Maximum default for a directory: 777 (rwxrwxrwx)

The most common umask value is 022:

TypeMax DefaultSubtract umask (022)ResultMeaning
File666- 022644Owner rw, group r, others r
Directory777- 022755Owner rwx, group r-x, others r-x
# Check current umask valueumask# Set a more restrictive umask (only owner can read/write new files)umask 077# Set the standard umaskumask 022

⚡ Exam Tip: The umask value is NOT directly applied — it is subtracted from the defaults. A umask of 022 results in files with 644 and directories with 755.

⭐ Special Permissions: SUID, SGID, Sticky Bit

Beyond the basic rwx permissions, Linux has three special permission bits that are important to know for advanced usage and exams:

SUID (Set User ID)

When SUID is set on an executable file, it runs with the permissions of the file owner, not the user who launched it. This is how the passwd command works — it runs as root even when called by a regular user, allowing them to change their own password.

# Set SUIDchmod u+s filename# orchmod 4755 filename

SGID (Set Group ID)

When SGID is set on a directory, new files created inside that directory inherit the directory's group rather than the creator's primary group. This is useful for shared project directories.

# Set SGID on a directorychmod g+s /shared/project# orchmod 2755 /shared/project

Sticky Bit

The sticky bit on a directory means that only the file owner, the directory owner, or root can delete or rename files inside it — even if others have write permission. The /tmp directory always has the sticky bit set.

# Set sticky bitchmod +t /shared/temp# orchmod 1755 /shared/temp# Check — sticky bit shows as 't' in the others execute positionls -ld /tmp# Output: drwxrwxrwt ... /tmp

💡 According to AWS documentation, proper file permission management — including SUID, SGID, and sticky bits — is a key part of securing Linux-based EC2 instances and containers. These permissions prevent privilege escalation attacks. 📚 Source:AWS EC2 Security Best Practices

📝 Overall Summary

  • SSH (Secure Shell): Protocol for securely connecting to remote Linux servers. Provides an encrypted channel.
  • Password-based SSH: Less secure — requires editing /etc/ssh/sshd_config and restarting the SSH service. Amazon Linux disables this by default.
  • Key-based SSH: The recommended method — private key stays on your laptop, public key is stored in ~/.ssh/authorized_keys on the server.
  • ssh-keygen: Command to generate an SSH key pair. Use -t rsa -b 4096 for strong RSA encryption.
  • ssh-copy-id: Command to copy your public key to a server automatically. Use Git Bash on Windows.
  • File permissions: Every Linux file has three permission types (read/write/execute) for three categories (owner/group/others).
  • ls -l: Shows the permission string, owner, group, and other details for each file.
  • chmod: Command to change permissions — supports symbolic method (chmod o+rwx) and numeric/octal method (chmod 755).
  • chown / chgrp: Change file ownership and group ownership respectively. Requires root/sudo.
  • umask: Controls the default permissions applied when new files and directories are created.
  • Special bits: SUID runs files as the owner; SGID inherits group on directories; Sticky bit prevents other users from deleting files in shared directories.

    📸 Screenshot: sshd_config with password auth disabled — three settings showing 'no'

🤔 Reflection Questions

1. Why does Amazon Linux use SSH key-based authentication by default instead of passwords?

💡 Hint

Think about what happens if two people know the same password. What are the risks? Then think about why having a physical private key file is more secure.

2. You create a script file and try to run it but get "Permission denied." What is likely the issue and how do you fix it?

💡 Hint

Check whether the file has the execute permission. What command would you use? Which permission category (u/g/o) would you most likely need to update?

3. A folder has permissions drwx------. Who can enter this folder? Can root access it?

💡 Hint

Break down the permission string: d = directory, first three = owner, middle three = group, last three = others. Root is special — it bypasses permission checks entirely.

4. What is the difference between using ls -l and ls -ld on a directory path?

💡 Hint

One shows what's inside the directory. The other shows the permissions of the directory itself as an object in the filesystem.

5. If you want a script to be executable by the owner only but readable by everyone, what chmod command would you use (numeric method)?

💡 Hint

Owner: read + write + execute = 4+2+1 = 7. Group: read only = 4. Others: read only = 4. Put them together.

6. Why is it important to set chmod 400 or chmod 600 on your private SSH key file?

💡 Hint

What happens if group or others can read your private key? SSH will actually refuse to use a key file that is "too open" (it shows an error about unprotected private key file).
