What is an AMI?

Amazon Machine Image (AMI)

Pre-configured template containing OS, applications, files, and configurations needed to launch EC2 instances

💡 Think of it like: A cookie cutter for servers - one template creates unlimited identical instances

⚡ The Power: Configure once → Deploy 100 servers in 5 minutes

AMI Components

  • 🖥️ Operating System - Linux, Windows, etc.
  • 📦 Applications - Pre-installed software
  • 📄 Files - Configuration files, scripts
  • ⚙️ Configuration Settings - System parameters

Result: Rapid, consistent server deployment

5 Types of AMIs

  • ✅ Official AWS - Highest trust, AWS-maintained (Amazon Linux, Ubuntu)
  • 🛒 Marketplace - Verified vendors, pre-configured software
  • 🏢 Third-Party - External vendors, use with caution
  • ❌ Community - UNVERIFIED, never use for production
  • ⭐ Custom - Your templates, production standard

⚠️ Critical Warning

Community AMIs Are Dangerous

Why: Zero verification from AWS

Risks: Malware, backdoors, crypto miners, vulnerabilities

✅ Rule: NEVER use Community AMIs for production

💡 Exam Alert: Questions will test if you know Community AMIs lack verification

AMI vs EC2 Instance

AMI = Blueprint/Template

Static, unchanging, defines software configuration

Storage cost only (~$0.05/GB/month)

EC2 Instance = Running Server

Live, dynamic, consuming resources

Per-hour/per-second billing

One AMI → Unlimited Instances

The AMI Lifecycle

  • 1️⃣ Start with Official AMI (Amazon Linux 2023)
  • 2️⃣ Launch EC2 instance from AMI
  • 3️⃣ Customize instance (install apps, configure)
  • 4️⃣ Create new Custom AMI from instance
  • 5️⃣ Launch production instances from Custom AMI
  • 🔄 Repeat for continuous improvement

Why Linux Dominates Cloud

70% of EC2 instances run Linux

  • 💰 Zero Licensing Costs - Free vs Windows fees
  • ⚡ Lower Resource Usage - Smaller instances needed
  • 🤖 Superior Automation - CLI-friendly
  • 🐳 Container Native - Docker/Kubernetes built for Linux
  • 🔒 Stability & Security - Runs months without reboots

Popular Linux Distributions

  • 🟠 Amazon Linux 2023 - AWS-optimized, free, recommended
  • 🟧 Ubuntu Server - Popular for development, free
  • 🔴 Red Hat Enterprise Linux - Enterprise support, paid

All use same Linux kernel, different tools/support

Linux System Architecture

  • 6️⃣ User Applications - What you run (Apache, MySQL)
  • 5️⃣ Shell - Command interface (bash)
  • 4️⃣ GNU Utilities - Tools (ls, grep, awk)
  • 3️⃣ System Libraries - Reusable code
  • 2️⃣ Linux Kernel - Core OS (manages everything)
  • 1️⃣ Hardware - Physical/virtual resources

Apps never touch hardware directly - kernel controls all

CLI vs GUI

GUI (Graphical) - Click buttons, visual

Easier for beginners, slower for automation

CLI (Command-Line) - Type commands, text

Steeper learning curve, powerful automation

💡 Cloud = CLI for automation, scripts, Infrastructure as Code

EC2 Launch Requirements

  • 1️⃣ AMI - Software configuration template
  • 2️⃣ Instance Type - Hardware specs (t3.micro, m5.large)
  • 3️⃣ Key Pair - SSH authentication (.pem file)
  • 4️⃣ Security Group - Virtual firewall rules
  • 5️⃣ VPC/Network - Network placement
  • 6️⃣ Storage (EBS) - Persistent volumes

💰 EC2 Instance States & Billing

Running - 💰 FULL CHARGES (compute + storage)

Stopped - 💵 Storage charges only (~90% savings)

Terminated - ❌ Zero charges (data deleted)

⚡ Pro Tip: Stop instances when not in use to save money!

⚠️ Common Mistakes

❌ Mistake #1: Community AMIs

Never use for production - unverified security risk

❌ Mistake #2: Lost Private Keys

Lose your .pem file = permanent loss of access

✅ Back up keys securely!

❌ Mistake #3: Running Instances 24/7

Forgetting to stop = huge bills

✅ Set billing alerts, stop when done

🎓 Key Exam Points

  • ✅ AMIs are region-specific (must copy to other regions)
  • ✅ Community AMIs = unverified, avoid for production
  • ✅ Running state = full billing, Stopped = storage only
  • ✅ Security Groups are stateful (return traffic auto-allowed)
  • ✅ SSH uses port 22 (Linux), RDP uses port 3389 (Windows)
  • ✅ Lost private key = no recovery possible
