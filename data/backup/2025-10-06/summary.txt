# 1. Why cloud exists

From page 1.

Traditional on-premise data centers have problems.

* High **CapEx**. You buy servers first.
* Ongoing **OpEx**. Power, cooling, staff.
* Hard to scale.
* Low efficiency.

Cloud fixes this.

You use a **Cloud Service Provider** like AWS.
You get servers, storage, and networks on demand.
You pay only for what you use.

This is called **pay as you go**.

---

# 2. On-prem vs Cloud

From page 1.

**On-premise**

* You own the servers
* You maintain hardware
* You handle failures
* Scaling is slow

**Cloud**

* Provider owns hardware
* You rent virtual servers
* Scaling is instant
* Cost follows usage

---

# 3. Virtualization

From page 2.

Virtualization lets one physical server run many virtual machines.

AWS uses virtualization to split big servers into many small ones.

This is how thousands of customers share the same data centers safely.

---

# 4. AWS global infrastructure

From page 2.

AWS is not one data center.

It is spread across the world.

### Region

A geographic area like Mumbai, London, or US East.

### Availability Zone

Each region has multiple AZs.
Each AZ is a separate data center.

If one AZ fails, others keep running.

This gives **high availability** and **fault tolerance**.

---

# 5. AWS login and access

From page 3.

You log in to AWS in three ways.

* AWS Management Console
* AWS CLI
* AWS SDK

All connect to your AWS account.

---

# 6. Authentication vs Authorization

From page 3 and 4.

**Authentication**
Who you are.
Email, password, MFA.

**Authorization**
What you can do.
Permissions.
Actions.

MFA means more than one proof.
Password plus OTP or app.

---

# 7. EC2 and Compute

From page 4.

EC2 means Elastic Compute Cloud.

It is a virtual server in AWS.

It is part of **IaaS**.
Infrastructure as a Service.

You can:

* Create servers
* Start and stop
* Resize them
* Delete them

These are cloud based virtual machines.

---

# 8. What is an AMI

From page 5, 6, 7.

AMI means **Amazon Machine Image**.

It is a template for creating EC2 instances.

It contains:

* Operating system
* Installed software
* Configuration

You do not install everything again and again.
You launch from an AMI.

Think of it as a ready made system image.

---

# 9. What an EC2 instance contains

From page 6.

An EC2 instance has:

* CPU
* Memory
* Storage
* Network
* OS
* Applications

Security controls it.

Security Groups act as firewalls.

---

# 10. Types of AMIs

From page 7 and 8.

There are four main types.

### Quick Start AMIs

Provided by AWS.
Basic Linux and Windows.

### Marketplace AMIs

From vendors.
Preinstalled software like databases.

### Community AMIs

Shared by other users.

### Custom AMIs

Created by you.
You take your EC2 and save it as an image.

---

# 11. Operating Systems

From page 8 and 9.

Two main types.

### Linux

Open source.
Free.
Based on Unix.

Uses Linux kernel.

### Windows

Owned by Microsoft.
Not free.

Linux is used heavily in cloud because it is free and flexible.

---

# 12. Linux internals

From page 9 and 10.

Linux OS has layers.

* User apps
* Utilities and libraries
* Kernel
* Hardware

Kernel talks to hardware.
Apps talk to kernel.

Linux plus GNU tools make Linux OS.

---

# 13. Linux distributions

From page 10.

Different companies package Linux.

These are called distros.

Examples:

* Ubuntu
* RedHat
* CentOS
* SUSE
* Debian
* Amazon Linux

They all use Linux kernel but have different tools and support.

---

# 14. Custom AMI flow

From page 11.

You take a running EC2.
You add software.
You configure it.
You create an AMI from it.

That AMI becomes a template.

You can launch many identical servers from it.

---

# 15. CLI vs GUI

From page 12 and 13.

### GUI

Graphical User Interface.
You click buttons.

### CLI

Command Line Interface.
You type commands.

CLI talks to OS through a shell.
Shell talks to kernel.
Kernel talks to hardware.

Both do the same thing.
One is visual.
One is text based.
