🔐 1. Multi-Factor Authentication (MFA)

What is MFA?

Multi-Factor Authentication (MFA) means using two or more verification methods to prove your identity when logging into AWS.

Definition: MFA requires both something you know (password) and something you have (one-time code from a device) to access your AWS account.

Let's use a real-world analogy:

🏦 The Bank Vault Analogy

Imagine a bank vault that requires two keys to open:

  • Key 1: Your password (something you memorized)
  • Key 2: A physical key card (something you physically carry)

A thief might steal one key, but having BOTH keys at the same time is much harder. That's exactly how MFA protects your AWS account!

Figure 1: MFA Two-Factor Protection - Password alone isn't enough

How MFA Works in AWS

Here's the complete authentication flow when MFA is enabled:

Figure 2: Complete MFA Login Workflow

Step-by-Step Login Process:

  1. Step 1: You enter your email and password (something you know)
  2. Step 2: AWS validates your credentials
  3. Step 3: AWS prompts you for an MFA code
  4. Step 4: You open your authenticator app on your phone
  5. Step 5: You see a 6-digit code that changes every 30 seconds
  6. Step 6: You enter this code in AWS
  7. Step 7: AWS verifies the code and grants access

⚡ Key Security Point:

Even if a hacker steals your password, they cannot log in without the MFA code from your physical device. This is why MFA is considered essential for all production AWS accounts.

Types of MFA Devices in AWS

AWS supports three main types of MFA devices:

Figure 3: MFA Device Types - Choose what works best for you

1️⃣ Virtual MFA (Most Common)

Virtual MFA uses an app on your smartphone to generate codes.

Popular Virtual MFA Apps:

App Name Platforms Why Use It
Google Authenticator iOS, Android Simple, free, widely used
Authy iOS, Android, Desktop Cloud backup, multi-device sync
Microsoft Authenticator iOS, Android Good for Microsoft ecosystem
AWS Virtual MFA Browser extension AWS-specific, desktop option

✅ Recommended Choice: Use Google Authenticator or Authy for beginners. They're free, easy to set up, and work with all AWS accounts.

2️⃣ Hardware MFA Token

A physical device that generates codes without needing a phone.

When to Use Hardware MFA:

  • High-security environments (banks, government)
  • Users without smartphones
  • Offline environments
  • Compliance requirements

Cost: $10-$50 per device

3️⃣ Security Key (U2F/FIDO)

A USB physical key like YubiKey that you plug into your computer.

Security Key Features:

  • Most secure option (phishing-resistant)
  • No codes to type (tap the key)
  • Works offline
  • Popular choice: YubiKey ($25-$80)

Setting Up MFA Step-by-Step

Let's walk through enabling Virtual MFA using Google Authenticator (the most common method).

📋 Prerequisites

  • ✅ AWS account with Root user access
  • ✅ Smartphone (iOS or Android)
  • ✅ Google Authenticator app installed (free from App Store/Play Store)

Part 1: Install the Authenticator App

Step 1: Download Google Authenticator

  • iPhone: Open App Store → Search "Google Authenticator" → Install
  • Android: Open Play Store → Search "Google Authenticator" → Install

💡 Alternative: You can use Authy, Microsoft Authenticator, or any app that supports TOTP (Time-based One-Time Password).

Part 2: Enable MFA in AWS Console

Step 2: Sign in as Root User

1. Go to: https://aws.amazon.com
2. Click "Sign In to the Console"
3. Select "Root user"
4. Enter your root email and password
5. Click "Sign in"

Step 3: Navigate to Security Credentials

1. Click your account name (top-right corner)
2. Select "Security credentials"
3. Or go directly to IAM Dashboard → Your Security Credentials

Figure 4: Finding Security Credentials in AWS Console

Step 4: Assign MFA Device

1. Scroll down to "Multi-factor authentication (MFA)" section
2. Click "Assign MFA device" button
3. You'll see a popup window

Step 5: Choose Device Type

1. Enter a device name: "my-phone-mfa" (or any name you like)
2. Select "Authenticator app"
3. Click "Next"

Step 6: Scan the QR Code

1. AWS displays a QR code on screen
2. Open Google Authenticator app on your phone
3. Tap the "+" button (bottom-right)
4. Select "Scan a QR code"
5. Point your camera at the QR code on your computer screen
6. The app adds AWS to your account list

⚠️ Can't Scan QR Code?

Click "Show secret key" under the QR code. Manually enter this text into your authenticator app instead.

Step 7: Enter Two Consecutive MFA Codes

1. Look at Google Authenticator app
2. You'll see a 6-digit code (e.g., 123456)
3. Enter this code in "MFA code 1" field
4. Wait 30 seconds for the code to refresh
5. Enter the NEW code in "MFA code 2" field
6. Click "Add MFA"

💡 Why Two Codes?

AWS asks for two consecutive codes to verify your authenticator app is correctly synchronized with AWS servers. This prevents timing issues.

Step 8: Verification

✅ Success Indicators:

  • Green success message appears
  • MFA device shows "Active" status
  • Device name appears in MFA section

Part 3: Test Your MFA Setup

Step 9: Sign Out and Test

1. Click your account name → Sign out
2. Sign in again with email and password
3. AWS now prompts for MFA code
4. Open Google Authenticator → Copy the 6-digit code
5. Enter code in AWS → Sign in
6. ✅ You're in!

Figure 5: Testing Your MFA Setup - The Complete Flow

MFA Best Practices

🔒 Security Best Practices

Practice Why It Matters
Always enable MFA on the Root user account Root user has unlimited access - highest security priority
Enable MFA on all IAM admin users Admin users can create/delete resources and incur costs
Save backup codes in a secure location You can recover access if you lose your phone
Use Authy for cloud backup Allows multi-device access and recovery
Never share MFA codes Defeats the purpose of two-factor authentication

❌ Common MFA Mistakes to Avoid

Mistake #1: Only enabling MFA on IAM users, not Root

Impact: Root account remains vulnerable - hackers target root access first

✅ Solution: Enable MFA on Root user FIRST, then on IAM users

Mistake #2: Losing phone without backup

Impact: You're locked out of your own AWS account

✅ Solution: Save backup codes during setup OR use Authy with cloud backup

Mistake #3: Using same MFA app for personal and work accounts

Impact: Security risk if phone is compromised

✅ Solution: Use separate MFA apps or dedicated work phone for company AWS accounts

🎓 Exam Tips for MFA

💡 For AWS Certification Exams:

  • MFA is always the recommended answer for securing root and privileged IAM accounts
  • Know the three MFA types: Virtual, Hardware Token, Security Key
  • Virtual MFA uses TOTP (Time-based One-Time Password) protocol
  • MFA codes change every 30 seconds
  • AWS requires two consecutive MFA codes during device registration to verify synchronization

💰 2. AWS Budget Alerts

What are Budget Alerts?

AWS Budget Alerts are notifications that warn you when your AWS spending reaches certain thresholds.

Definition: AWS Budgets is a service that lets you set custom spending limits and receive email alerts when actual or forecasted costs exceed your defined thresholds.

Think of it like this:

💳 The Credit Card Limit Analogy

Imagine your credit card company sending you alerts:

  • Alert 1: "You've spent $80 of your $100 monthly limit" (80% warning)
  • Alert 2: "You've reached your $100 limit!" (100% warning)

AWS Budget Alerts work the same way - you set a spending limit, and AWS notifies you as you approach it. This prevents surprise bills at the end of the month!

Figure 6: Budget Alert Concept - Get warned before you overspend

How Budget Alerts Work

Here's the complete budget monitoring flow:

Figure 7: Budget Monitoring Workflow

The Budget Monitoring Process:

  1. You create AWS resources: EC2 instances, S3 buckets, databases, etc.
  2. AWS tracks usage: Every action (compute time, storage, data transfer) generates costs
  3. Billing system updates: AWS calculates your running total
  4. Budget service monitors: Compares your spending to your budget threshold
  5. Alert triggers: When threshold is crossed, email is sent
  6. You take action: Stop resources, optimize usage, or increase budget

Types of Budget Tracking

AWS can alert you based on two types of costs:

Cost Type Description When to Use
Actual Cost What you've already spent Track current spending in real-time
Forecasted Cost What AWS predicts you'll spend by month-end Get early warnings before month ends

💡 Understanding Forecasted Costs:

AWS analyzes your spending pattern and predicts your end-of-month total. For example:

  • Day 15 of month: You've spent $30
  • AWS forecast: "At this rate, you'll spend $60 by month-end"
  • If your budget is $50, you get an alert NOW (not later)

Types of AWS Budgets

Figure 8: Four Main Types of AWS Budgets

1️⃣ Zero Spend Budget

Purpose: Alerts you if spending exceeds $0.01 - perfect for Free Tier users

✅ Best For:

  • Brand new AWS accounts
  • Students learning AWS
  • Free Tier users who want zero charges
  • Sandbox/learning environments

How it works:

Budget Amount: $0.01
Alert Threshold: Any spending above $0.01
Result: Email sent the MOMENT you incur charges

⚡ Pro Tip: This is the FIRST budget you should set up when creating an AWS account. It prevents accidental charges from misconfigured services.

2️⃣ Monthly Cost Budget

Purpose: Set a monthly spending limit (e.g., $10, $50, $100)

💡 Example Scenario:

You're a student with $20/month to spend on AWS learning:

  • Set budget: $20/month
  • Alert at 80%: Email when you hit $16
  • Alert at 100%: Email when you hit $20
  • Alert at 110%: Email if you go over $22

Configuration Options:

Alert Point Budget Amount: $50 When Alert Triggers
50% threshold $25 Halfway through budget
80% threshold $40 Getting close to limit
100% threshold $50 Reached your limit
110% threshold $55 Over budget - take action!

3️⃣ Usage Budgets

Purpose: Track service usage instead of costs (e.g., EC2 hours, S3 storage GB)

When to Use Usage Budgets:

Example 1: Track EC2 running hours

  • Budget: 100 hours/month
  • Alert at 80 hours
  • Useful for: Ensuring instances are stopped when not in use

Example 2: Track S3 storage

  • Budget: 100 GB storage
  • Alert at 90 GB
  • Useful for: Preventing runaway storage costs

4️⃣ Savings/Reservation Budgets

Purpose: Monitor Reserved Instances and Savings Plans utilization

💼 Advanced Use Case:

This is for organizations with Reserved Instances (RIs) or Savings Plans who want to ensure they're getting their money's worth.

Example: You bought $1000/month in Reserved Instances, but only using 70% of capacity - budget alerts you to optimize usage.

📝 Overall Summary

Here's everything we covered in Session 4:

🔐 Multi-Factor Authentication (MFA)

  • MFA adds extra security layer requiring password + one-time code from your phone
  • Three types available: Virtual MFA (Google Authenticator), Hardware Token, Security Key (YubiKey)
  • Virtual MFA is most common - free, easy to set up, works on smartphones
  • Enable on Root user FIRST - this is your highest security priority
  • MFA codes change every 30 seconds using TOTP (Time-based One-Time Password)
  • Always save backup codes in case you lose your phone
  • AWS requires two consecutive codes during setup to verify synchronization

💰 AWS Budget Alerts

  • Budget Alerts notify you when spending crosses thresholds you define
  • Four budget types: Zero Spend, Monthly Cost, Usage, Savings/Reservations
  • Zero Spend Budget alerts at $0.01 - perfect for Free Tier accounts
  • Can track actual OR forecasted costs - forecasted gives early warnings
  • First 2 budgets are free - set up Zero Spend + Monthly Cost on day one
  • Configure multiple alert thresholds (50%, 80%, 100%) for better control
  • Alerts sent via email or SNS - make sure emails are actively monitored

⚖️ MFA vs Budget Alerts

  • MFA protects security - prevents unauthorized access to your account
  • Budget Alerts protect costs - prevents unexpected bills and overspending
  • Both are essential for production AWS accounts
  • Set up both on day one when creating new AWS account

🎯 Key Takeaways for Exams

  • MFA is ALWAYS the right answer for securing root and privileged accounts
  • Zero Spend Budget is recommended for all Free Tier accounts
  • AWS Budgets can alert on actual costs, forecasted costs, or service usage
  • Virtual MFA uses authenticator apps and costs nothing
  • Budget alerts require email or SNS topic for notifications

⏱️ Time: 15-20 minutes

💰 Cost: Free (this is your second budget - first 2 are free)

What You'll Build

A budget that tracks monthly spending and alerts you at 80% and 100% of your $20 monthly limit.

Step-by-Step Instructions

Part 1: Create Custom Budget

  1. Billing → Budgets → Create budget
  2. Select "Customize (advanced)"
  3. Budget type: "Cost budget"
  4. Click "Next"

Part 2: Set Budget Amount

  1. Budget name: "MonthlyLimit20"
  2. Period: "Monthly"
  3. Budget effective dates: "Recurring budget"
  4. Start month: Current month
  5. Budgeting method: "Fixed"
  6. Enter budgeted amount: $20.00
  7. Click "Next"

Part 3: Configure Alerts

  1. Alert #1: 80% of budgeted amount ($16.00)
    • Threshold: 80%
    • Email: your-email@example.com
  2. Click "Add alert threshold"
  3. Alert #2: 100% of budgeted amount ($20.00)
    • Threshold: 100%
    • Email: same email
  4. Click "Next"

Part 4: Review and Create

  1. Review all settings
  2. Click "Create budget"
  3. Confirm email subscription (check inbox)

Verification Checklist

✅ Success Indicators:

  • Two active budgets now: "MyZeroSpendBudget" + "MonthlyLimit20"
  • Both show "Active" status
  • Email confirmations received for both alert thresholds
  • Budget details show $16 and $20 thresholds

Clean Up

⚠️ Keep both budgets active! They provide ongoing protection.

💡 Cost Note: First 2 budgets are free. If you create a 3rd budget, AWS charges $0.02/day ($0.60/month).

🤔 Reflection Questions

Test your understanding with these thought-provoking questions. Try to answer before viewing hints.

1. Why is MFA called "multi-factor" authentication?

💡 Hint

Think about the word "factor" - what different types of proof are you providing? Consider "something you know" vs "something you have".

2. If you could only set up ONE security measure for a new AWS account, would you choose MFA or Budget Alerts? Why?

💡 Hint

There's no single "right" answer! Consider: What's more damaging - a hacker gaining access or getting a large unexpected bill? What's more likely to happen?

3. Why does AWS require TWO consecutive MFA codes during device setup instead of just one?

💡 Hint

Think about timing. MFA codes change every 30 seconds. What if your phone's clock is off by a few minutes? How does AWS know your app is properly synchronized?

4. How would you explain the difference between "actual cost" and "forecasted cost" budgets to a non-technical friend?

💡 Hint

Use a personal finance analogy. Think about tracking money you've already spent vs predicting what you'll spend by month-end based on current habits.

5. A company has 50 employees who need AWS access. Should they all share one Root user account with MFA, or should each have their own IAM account? Why?

💡 Hint

Consider accountability, security, and the principle of least privilege. What happens if someone leaves the company? How do you track who did what?

6. Why is a Zero Spend Budget better than a $5/month budget for Free Tier users?

💡 Hint

Think about Free Tier limits. If you stay within Free Tier, what should your bill be? When would you WANT to be notified?

7. If your phone with Google Authenticator gets stolen, how would you still access your AWS account?

💡 Hint

Think about backup options. What should you have saved during MFA setup? What recovery methods does AWS provide?

8. Why doesn't AWS just enable MFA by default on all accounts if it's so important for security?

💡 Hint

Consider user experience and access. What happens if someone doesn't have a smartphone? What if they lose their device? Balance security vs usability.
