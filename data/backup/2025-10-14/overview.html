🎯 Introduction

Linux is an open-source, Unix-like operating system kernel combined with GNU tools to create a complete operating system. It powers the majority of cloud infrastructure, including AWS EC2 instances, web servers, and enterprise systems. Understanding Linux is fundamental for cloud engineers, DevOps practitioners, and system administrators.

Figure 1: Linux Architecture - Layered system from hardware to user applications

This technical overview covers Linux operating system fundamentals, architectural components, file system hierarchy, and comparisons with Windows-based systems. These concepts are essential for managing AWS EC2 Linux instances and understanding cloud infrastructure.

💻 Operating System Fundamentals

What is an Operating System?

An operating system is a software program that acts as an intermediary between users/applications and the underlying hardware. It manages hardware resources (CPU, RAM, storage) and provides services to applications.

Core Components

Component Function Purpose
Hardware Physical resources CPU, RAM, storage, network interfaces
Kernel Core OS component Process management, memory management, device drivers
Shell User interface Command interpreter, accepts user commands
System Libraries Pre-defined functions Standard programming interfaces, reusable code
Utilities System tools Day-to-day operational commands and programs
Applications User programs Software that performs user tasks

Why Operating Systems Are Needed

Without an operating system, software cannot interact with hardware. The OS provides abstraction layers that allow applications to request resources without knowing hardware-specific details.

Figure 2: OS as intermediary between applications and hardware

Operating System Responsibilities

  • Process Management: Creating, scheduling, and terminating processes
  • Memory Management: Allocating and deallocating RAM to processes
  • File System Management: Organizing and accessing files on storage devices
  • Device Management: Controlling hardware devices through drivers
  • Security: User authentication, access control, permissions
  • Networking: Managing network connections and protocols

📜 Unix History and Evolution

The Birth of Unix (1960s)

In the 1960s, Unix was developed as a multi-user, multi-tasking operating system using the C programming language. It introduced revolutionary concepts that influenced all modern operating systems.

Figure 3: Unix to Linux Timeline - Evolution from 1960s to 1990s

Unix Characteristics

Feature Description Impact
Multi-user Multiple users can work simultaneously Server environments, shared resources
Multi-tasking Multiple processes run concurrently Efficient resource utilization
Hierarchical File System Tree-like directory structure Organized data storage
Command Line Interface Text-based interaction Powerful scripting and automation
Portable Written in C, not assembly Runs on different hardware platforms

Unix Philosophy

Unix introduced key design principles that Linux inherited:

  • Everything is a file: Devices, processes, and data are treated as files
  • Small, single-purpose tools: Each utility does one thing well
  • Composability: Tools can be combined using pipes and redirection
  • Plain text configuration: Configuration files are human-readable text

Unix Limitations

Unix was proprietary and required licensing fees. This created a barrier to adoption and modification, leading to the need for a free, open-source alternative.

🔧 Linux Development and GNU

The Need for Free Unix (1980s-1990s)

By the 1980s, Unix was widespread but expensive. The GNU Project (GNU's Not Unix) was started to create a free Unix-like operating system. However, GNU lacked a kernel—the core component of an OS.

Linus Torvalds and the Linux Kernel (1991)

In 1991, Linus Torvalds, a 21-year-old Finnish student, developed the Linux kernel as a free alternative to commercial Unix kernels. He released it under the GPL (GNU General Public License), allowing anyone to use, modify, and distribute it.

Figure 4: Linux = Kernel + GNU Tools

GNU + Linux = Complete OS

Component Provider Function
Kernel Linus Torvalds Core OS, hardware management
Shell GNU Project Bash shell, user interface
Utilities GNU Project ls, cp, mv, grep, etc.
Libraries GNU Project glibc, standard C library
Compiler GNU Project GCC (GNU Compiler Collection)

Open Source Advantages

  • Free of Cost: No licensing fees
  • Source Code Access: Full visibility into how the OS works
  • Community Contributions: Thousands of developers contribute
  • Security: Transparent code review, rapid vulnerability patching
  • Customization: Modify to suit specific needs

Linux Philosophy

Linux inherited Unix philosophy and added:

  • Collaboration: Global community-driven development
  • Meritocracy: Code quality determines acceptance
  • Transparency: All development is public
  • Freedom: Users control their own systems

🏗️ Operating System Architecture

Layered Architecture Model

Linux uses a layered architecture where each layer provides services to the layer above and uses services from the layer below.

Figure 5: Linux Layered Architecture - Request flow from user to hardware

Layer Breakdown

1. Hardware Layer

Physical components: CPU, RAM, storage (HDD/SSD), network interfaces, peripherals.

2. Kernel Layer

The kernel is the core of the operating system. It has unrestricted access to hardware and manages:

Kernel Subsystem Responsibility
Process Scheduler Allocates CPU time to processes
Memory Manager Manages RAM allocation and virtual memory
File System Organizes and accesses files on disk
Device Drivers Interfaces with hardware devices
Network Stack Handles network protocols (TCP/IP)

3. System Libraries Layer

Pre-compiled functions that programs use to interact with the kernel. The most important is glibc (GNU C Library), which provides standard C functions like printf, malloc, etc.

4. Shell Layer

The shell is a command interpreter that accepts user commands and translates them into kernel-level operations. Common shells:

  • Bash: Bourne Again Shell (most common)
  • Zsh: Z Shell (feature-rich)
  • Fish: Friendly Interactive Shell
  • Dash: Debian Almquist Shell (lightweight)

5. Utilities and Applications Layer

User-facing programs and tools that perform specific tasks. Examples: ls, grep, vim, web browsers, databases.

How a Command Executes

User types: ls /home
↓
Shell parses command
↓
Shell calls ls utility
↓
ls utility uses system libraries (glibc)
↓
Libraries make system calls to kernel
↓
Kernel accesses file system
↓
Kernel retrieves directory contents from disk
↓
Data flows back up the layers
↓
Shell displays output to terminal

System Calls

System calls are the interface between user space (applications) and kernel space. Examples:

System Call Purpose Example Use
open() Open a file Reading configuration files
read() Read data from file Loading data into memory
write() Write data to file Saving logs
fork() Create new process Starting a program
exec() Execute program Running commands

📁 Linux File System Hierarchy

Everything is a File Philosophy

In Linux, everything is represented as a file: regular files, directories, devices (keyboard, mouse, disk), processes, network sockets, and even system information.

Single Root Directory Structure

Unlike Windows (which has multiple drives: C:, D:, E:), Linux has a single root directory denoted by / (forward slash). All files and directories branch from this root.

Figure 6: Linux File System Hierarchy - All paths start from /

Standard Directory Structure

Directory Purpose Contents
/ Root directory Top-level directory, everything starts here
/bin Essential binaries Basic commands: ls, cp, mv, cat, bash
/sbin System binaries System administration commands: fdisk, iptables, reboot
/etc Configuration files System-wide configuration: /etc/passwd, /etc/ssh/sshd_config
/home User home directories /home/ec2-user, /home/john - user files and settings
/root Root user home Home directory for root/administrator user
/var Variable data Log files (/var/log), databases, mail spools
/tmp Temporary files Temporary files, cleared on reboot
/usr User programs User applications, libraries, documentation
/opt Optional software Third-party applications manually installed
/lib System libraries Shared libraries needed by /bin and /sbin
/dev Device files Hardware devices: /dev/sda (disk), /dev/tty (terminal)
/proc Process information Virtual filesystem with kernel and process info
/sys System information Virtual filesystem with device and driver info
/boot Boot files Kernel, bootloader configuration
/mnt Mount points Temporary mount points for filesystems
/media Removable media Auto-mounted USB drives, CDs

Path Representation

Paths in Linux use forward slashes (/) as separators:

  • Absolute path: Starts from root: /home/ec2-user/file.txt
  • Relative path: Relative to current directory: ../folder/file.txt

Special Directories

Symbol Meaning Example
/ Root directory Topmost directory
~ User home directory ~ = /home/ec2-user
. Current directory ./script.sh runs script in current dir
.. Parent directory cd .. moves up one level

File System in AWS EC2

When you SSH into an EC2 Linux instance, you land in the user's home directory. For Amazon Linux, this is /home/ec2-user. The prompt shows:

[ec2-user@ip-172-31-10-88 ~]$

Breaking this down:

  • ec2-user: Current logged-in username
  • ip-172-31-10-88: Hostname (private IP)
  • ~: Current directory (tilde represents /home/ec2-user)
  • $: Standard user (not root)

If you switch to root user with sudo su -, the prompt changes:

[root@ip-172-31-10-88 ~]#

The # symbol indicates root/administrator privileges.

⚖️ Windows vs Linux Comparison

Structural Differences

Figure 7: Windows Drive-Based vs Linux Single Root Structure

Aspect Windows Linux
File System Root Multiple drives (C:, D:, E:) Single root directory (/)
Path Separator Backslash (\) Forward slash (/)
Case Sensitivity Case-insensitive Case-sensitive
Primary Interface GUI (Graphical) CLI (Command Line) on servers
User Model Administrator + Standard users Root + Standard users
Configuration Registry + config files Text files in /etc
Device Representation Drive letters (C:, D:) Files in /dev (e.g., /dev/sda1)
External Devices Assigned drive letters Mounted under /mnt or /media
Licensing Proprietary, paid Open source, free
Security Model UAC, Windows Defender File permissions, SELinux

Windows Directory Structure

Windows organizes files under the C: drive (primary OS drive):

  • C:\Windows: Operating system files
  • C:\Program Files: Installed applications (64-bit)
  • C:\Program Files (x86): 32-bit applications
  • C:\Users: User home directories
  • C:\Users\Username: Individual user files, Desktop, Downloads, Documents

Additional drives (D:, E:) are used for data storage or partitions.

Case Sensitivity Example

In Windows:

File1.txt == file1.txt == FILE1.TXT
(All refer to the same file)

In Linux:

File1.txt ≠ file1.txt ≠ FILE1.TXT
(Three different files)

This is critical when working with Linux—typos in capitalization will cause "file not found" errors.

Command Comparison

Task Windows Linux
List files dir ls
Change directory cd cd
Copy file copy cp
Move file move mv
Delete file del rm
Clear screen cls clear
Show path cd pwd

🌐 Linux Distributions

What is a Linux Distribution?

A Linux distribution (distro) is a complete operating system built around the Linux kernel. Each distro includes:

  • Linux kernel (core OS)
  • GNU tools (shell, utilities)
  • Package manager (software installation system)
  • Desktop environment (for GUI distros) or minimal tools (for servers)
  • Pre-installed software and configurations

Why Multiple Distros Exist

Linux's open-source nature allows anyone to create customized versions. Different distros target different use cases:

  • Server environments: Stability and security (CentOS, Ubuntu Server, Amazon Linux)
  • Desktop use: User-friendly GUI (Ubuntu Desktop, Linux Mint, Fedora Workstation)
  • Security/Penetration testing: Pre-installed hacking tools (Kali Linux, Parrot OS)
  • Embedded systems: Lightweight, minimal (Alpine Linux)
  • Enterprise: Commercial support (Red Hat Enterprise Linux, SUSE)

Popular Linux Distributions

Distribution Base Use Case Package Manager

AWS and Linux Distributions

In AWS EC2, when launching an instance, you select an AMI (Amazon Machine Image). Common Linux AMIs:

  • Amazon Linux 2: AWS's own distro, optimized for EC2, free tier eligible
  • Ubuntu Server: Popular for web applications
  • Red Hat Enterprise Linux: Enterprise support, costs extra
  • CentOS: Free RHEL alternative (being phased out)

Package Managers by Distro

Different distros use different package managers to install software:

Distro Family Package Manager Install Command Example
Debian/Ubuntu apt, apt-get sudo apt install nginx
Red Hat/CentOS/Amazon Linux yum, dnf sudo yum install nginx
Arch Linux pacman sudo pacman -S nginx
Alpine Linux apk apk add nginx

Choosing a Linux Distro

For cloud engineers working with AWS:

  • Amazon Linux 2: Best for AWS-specific workloads, includes AWS CLI pre-installed
  • Ubuntu Server: Large community, extensive documentation
  • Red Hat Enterprise Linux: Enterprise support, certified for compliance requirements

📝 Overall Summary

This session covered the foundational concepts of Linux operating systems:

  • Operating System Fundamentals: An OS acts as an intermediary between users/applications and hardware, managing resources like CPU, RAM, and storage through components including kernel, shell, libraries, and utilities.
  • Unix History: Developed in the 1960s using C programming language, Unix introduced multi-user, multi-tasking capabilities and the hierarchical file system. It was proprietary and required licensing fees.
  • Linux Development: In 1991, Linus Torvalds created the Linux kernel as a free alternative. Combined with GNU tools (shell, utilities, libraries), it formed a complete open-source operating system.
  • Linux Architecture: Uses a layered approach—hardware at the base, kernel managing resources, system libraries providing programming interfaces, shell interpreting commands, and applications/utilities at the top.
  • File System Hierarchy: Linux treats everything as files and uses a single root directory (/) unlike Windows' multiple drives. Important directories include /bin (binaries), /etc (configuration), /home (user directories), /var (logs), /tmp (temporary files).
  • Windows vs Linux: Key differences include Windows' drive-based structure vs Linux's single root, case-insensitive vs case-sensitive filenames, GUI-primary vs CLI-primary interfaces, and proprietary vs open-source models.
  • Linux Distributions: Various distros exist for different purposes—Amazon Linux for AWS, Ubuntu for general use, Kali/Parrot for security testing, CentOS/RHEL for enterprise servers. Each uses different package managers (apt, yum, dnf).
  • CLI Importance: Linux servers primarily use command-line interfaces for efficiency and automation. Understanding CLI is essential for cloud engineers managing EC2 instances.
  • Case Sensitivity: Unlike Windows, Linux treats File.txt and file.txt as different files, making exact capitalization critical.
  • AWS Integration: EC2 instances commonly use Amazon Linux or Ubuntu. When connecting via SSH, you land in the user's home directory (/home/ec2-user), indicated by the tilde (~) symbol in the prompt.

Understanding these Linux fundamentals is essential before diving into commands, user management, file permissions, and system administration tasks in subsequent sessions.
