💻 What is an Operating System?

The Bridge Between You and Your Computer

Imagine you want to watch a movie on your laptop. You double-click the video file, and it plays. Simple, right? But behind the scenes, a lot is happening:

  • The file needs to be read from your hard disk
  • Video data needs to be loaded into RAM (memory)
  • The CPU needs to decode the video
  • The graphics card needs to display it on your screen
  • The speakers need to play audio

Who coordinates all of this? The Operating System (OS).

💡 Operating System in Simple Terms:

An operating system is like a manager of a restaurant kitchen. You (the customer) place an order. The manager takes your order, tells the chef (CPU) what to cook, asks the pantry staff (storage) to bring ingredients, coordinates with waiters (memory) to serve you, and makes sure everything runs smoothly. You don't need to know how the kitchen works—you just enjoy your meal!

An operating system is software that acts as an intermediary between users or applications and the computer's hardware. It manages resources like the CPU, memory (RAM), storage (hard disk), and input/output devices.

What Does an Operating System Do?

Task What OS Does Real-World Analogy
Process Management Runs multiple programs at once Like juggling multiple tasks—cooking, cleaning, talking on phone
Memory Management Allocates RAM to programs Like giving each worker in a kitchen their workspace
File Management Organizes files and folders Like organizing books in a library with sections and shelves
Security Controls who can access what Like a security guard checking IDs before entry
Device Management Talks to keyboard, mouse, printer Like a translator helping people who speak different languages

Core Components of an OS

Every operating system has these key parts:

  • Kernel: The brain of the OS—manages hardware directly
  • Shell: The interface where you type commands (in Linux)
  • System Libraries: Pre-written code that programs use
  • Utilities: Tools like file viewers, text editors, calculators

Figure 2: How you interact with hardware through the OS

Why Can't We Use Hardware Directly?

Imagine if every time you wanted to save a file, you had to write code telling the hard disk exactly which sectors to write to, at what speed, with what voltage. That would be a nightmare!

The operating system provides abstraction—it hides the complexity of hardware and gives you simple commands like "save file" or "print document".

📜 The Unix Story (1960s)

Where It All Began

In the 1960s, computers were massive machines that filled entire rooms. They were expensive and only big companies or universities could afford them. Each computer had its own custom operating system, and if you wanted to run your program on a different computer, you'd have to rewrite it from scratch.

Then, something revolutionary happened. A group of developers created an operating system called Unix using a programming language called C.

Figure 3: From Unix (1960s) to Linux (1990s) - A 30-year journey

What Made Unix Special?

Unix introduced multi-user and multi-tasking capabilities, allowing multiple people to use the same computer simultaneously. Think of it like multiple people cooking in the same kitchen at the same time without interfering with each other.

Key Unix innovations:

  • Hierarchical File System: Organized files like a family tree (we still use this today!)
  • Command Line Interface: Type commands instead of clicking buttons
  • Portable: Because it was written in C, Unix could run on different types of computers
  • Everything is a file: Devices, programs, data—all treated as files

💡 The "Everything is a File" Philosophy:

In Unix (and Linux), even your keyboard is a file! Your mouse is a file! Your hard disk is a file! This might sound weird, but it makes things simpler. Instead of having different ways to interact with different devices, you use the same file operations (read, write, open, close) for everything.

The Problem with Unix

Unix was amazing, but there was a catch: Unix was proprietary software that required expensive licensing fees. Companies had to pay to use it, and you couldn't see or modify the source code.

This created a barrier. Students, hobbyists, and small companies couldn't afford Unix. The world needed a free alternative...

🚀 How Linux Was Born (1991)

Two Heroes of the Story

The birth of Linux involved two key players:

1. Richard Stallman and the GNU Project (1980s)

Richard Stallman started the GNU Project (GNU's Not Unix) to create a free Unix-like operating system. His team developed:

  • The Bash shell (where you type commands)
  • Utilities like ls, cp, mv (we'll learn these soon!)
  • Libraries that programs need
  • The GCC compiler to compile programs

But they were missing one crucial piece: the kernel (the core of the OS).

2. Linus Torvalds and the Linux Kernel (1991)

In 1991, a 21-year-old Finnish student named Linus Torvalds was frustrated with the limitations of existing systems. He decided to create his own kernel as a hobby project.

⚡ Fun Fact:

Linus originally wanted to call it "Freax" (a combination of "free," "freak," and "Unix"). But the person who hosted it on a server named the directory "Linux" (Linus + Unix), and the name stuck!

Linus released the Linux kernel under the GPL (GNU General Public License), making it free and open-source. This meant anyone could use it, modify it, and share it.

GNU + Linux = Complete Operating System

Figure 4: Linux kernel + GNU tools = Complete Linux OS

When you combine:

  • Linux kernel (created by Linus Torvalds) +
  • GNU tools (created by Richard Stallman's team)

You get a complete, free, open-source operating system!

What Does "Open Source" Mean?

Imagine if you bought a car, but the hood was welded shut. You can drive it, but you can't see how the engine works, and you can't fix or modify it yourself. That's proprietary software (like Windows).

Now imagine the car comes with a complete manual showing every part, and you're allowed to modify the engine, add new features, and even share your improvements with others. That's open source (like Linux)!

✅ Benefits of Open Source Linux:

  • Free of cost: No licensing fees
  • Transparency: You can see exactly how it works
  • Security: Thousands of developers review the code
  • Customization: Modify it to suit your needs
  • Community support: Global community helps each other

Linux is maintained by a global community of developers who contribute code, fix bugs, and improve security. It's not controlled by a single company—it belongs to everyone!

🏗️ How Linux Works - Architecture Explained

Think of Linux as a Building

Linux architecture is like a multi-story building:

  • Foundation: Hardware (CPU, RAM, disk)
  • Ground floor: Kernel (building security and management)
  • First floor: System libraries (shared facilities like elevators)
  • Second floor: Shell (reception desk where you make requests)
  • Top floors: Applications (offices where actual work happens)

Figure 5: Linux architecture layers - Each layer serves the layer above

Layer-by-Layer Explanation

Layer 1: Hardware (The Foundation)

This is your physical computer:

  • CPU: The brain that processes instructions
  • RAM: Short-term memory for running programs
  • Storage (HDD/SSD): Long-term memory for files
  • Network card: Connects to the internet
  • Keyboard, mouse, monitor: Input/output devices

Layer 2: Kernel (The Manager)

The kernel is the core of the Linux operating system that directly manages hardware resources. Think of it as the building manager who has keys to everything.

The kernel handles:

Task Analogy
Process Management Like a chef managing multiple dishes cooking at once
Memory Management Like a librarian assigning reading desks to students
File System Management Like a filing clerk organizing documents
Device Drivers Like translators helping you talk to foreigners
Security Like a bouncer checking IDs at the door

💡 Why You Can't Talk to Hardware Directly:

Imagine if every time you wanted to save a file, you had to tell the hard disk: "Move the read/write head to cylinder 42, sector 18, track 7, and write these bits: 01101000..." Impossible!

The kernel does this for you. You just say "save file," and the kernel handles all the complex hardware operations.

Layer 3: System Libraries (The Helpers)

System libraries are collections of pre-written code that programs use to perform common tasks. The most important is glibc (GNU C Library).

Analogy: Instead of every chef making their own knife, cutting board, and pots, they share common kitchen tools. Libraries are like shared tools that save programmers time.

Layer 4: Shell (The Reception Desk)

The shell is a command interpreter that accepts commands from users and translates them into actions the kernel can perform.

Think of the shell as a receptionist at a hotel:

  • You (guest): "I'd like room service."
  • Receptionist (shell): "Sure! Let me call the kitchen (kernel) for you."
  • Kitchen (kernel): "Got it! Sending food up."

Popular shells in Linux:

  • Bash: Bourne Again Shell (most common, default in most Linux systems)
  • Zsh: Z Shell (fancy features, used in macOS now)
  • Fish: Friendly Interactive Shell (beginner-friendly)

Layer 5: Utilities and Applications (The Workers)

These are the programs you actually use:

  • Utilities: Built-in tools like ls (list files), cp (copy), grep (search)
  • Applications: Software like web servers (Apache, Nginx), databases (MySQL), text editors (vim, nano)

How a Command Travels Through the Layers

Let's trace what happens when you type ls (list files) in the terminal:

Step 1: You type: ls /home
         ↓
Step 2: Shell receives the command
         ↓
Step 3: Shell finds the ls program (usually in /bin/ls)
         ↓
Step 4: ls program uses system libraries (glibc)
         ↓
Step 5: Libraries make system calls to the kernel
         ↓
Step 6: Kernel accesses the file system on the hard disk
         ↓
Step 7: Hard disk returns directory contents
         ↓
Step 8: Data flows back up: Kernel → Libraries → ls program
         ↓
Step 9: Shell displays the result on your screen

⚠️ Important Concept:

Users and programs cannot directly access hardware in Linux—all hardware access must go through the kernel for security and stability.

📁 Linux File System - Where Everything Lives

The "Everything is a File" Philosophy

Remember we mentioned this earlier? In Linux, everything is treated as a file:

  • Regular files (documents, photos) = Files ✓
  • Directories (folders) = Files ✓
  • Your keyboard = File ✓
  • Your hard disk = File ✓
  • Running programs (processes) = Files ✓
  • Network connections = Files ✓

This might seem weird, but it's actually brilliant! Instead of having different ways to interact with different things, you use the same file operations (read, write, open, close) for everything.

The Single Root Structure

Unlike Windows which has multiple drives (C:, D:, E:), Linux has a single root directory denoted by forward slash /.

💡 The Tree Analogy:

Think of the Linux file system as a tree:

  • Root (/): The trunk of the tree
  • Branches: Main directories like /home, /etc, /var
  • Leaves: Files and subdirectories

Everything grows from the root!

Figure 6: Linux file system tree - All paths start from / (root)

Important Directories Explained

When you connect to a Linux EC2 instance, you'll see these directories. Let's understand what each one does:

/ (Root Directory)

The top-level directory. Everything starts here. Think of it like "This PC" in Windows.

/home (User Home Directories)

/home contains personal directories for all standard users on the system.

Analogy: Like an apartment building where each resident has their own apartment:

  • /home/ec2-user = EC2 user's apartment
  • /home/john = John's apartment
  • /home/mary = Mary's apartment

Each user can only access their own apartment (directory) by default.

/root (Root User's Home)

The home directory for the root user (administrator). The root user has complete control over the entire system—like the building owner who has keys to all apartments.

⚠️ Important Distinction:

  • / = Root directory (the tree trunk)
  • /root = Root user's home directory (admin's apartment)

These are different things!

/bin (Essential Binaries)

/bin contains essential command-line programs that all users need, like:

  • ls (list files)
  • cp (copy)
  • mv (move)
  • cat (view file contents)
  • bash (the shell itself)

Think of /bin like a toolbox everyone can access.

/sbin (System Binaries)

Similar to /bin, but these are system administration tools that usually only the root user needs:

  • fdisk (partition disks)
  • reboot (restart system)
  • iptables (firewall configuration)

/etc (Configuration Files)

/etc stores system-wide configuration files in plain text format.

Examples:

  • /etc/passwd - List of all user accounts
  • /etc/ssh/sshd_config - SSH server configuration
  • /etc/hosts - DNS hostname mappings

Analogy: Like the main office of an apartment building where all records, rules, and settings are kept.

/var (Variable Data)

/var contains files that change frequently during system operation, especially log files.

  • /var/log - System and application logs
  • /var/log/messages - General system logs
  • /var/log/auth.log - Authentication logs (who logged in)

When troubleshooting, you'll spend a lot of time in /var/log!

/tmp (Temporary Files)

/tmp stores temporary files that are automatically deleted when the system reboots.

Analogy: Like scratch paper—useful for a moment, then thrown away.

/usr (User Programs)

Despite the name, /usr doesn't mean "user files"—it stands for "Unix System Resources." This is where most user-installed applications and their files live:

  • /usr/bin - Additional user programs
  • /usr/local - Locally installed software
  • /usr/share - Shared data like documentation

/opt (Optional Software)

For third-party applications that don't come with the OS. If you manually download and install software (like Java, custom applications), it often goes here.

/dev (Device Files)

/dev contains device files that represent hardware components.

Examples:

  • /dev/sda - First hard disk
  • /dev/sda1 - First partition on first disk
  • /dev/null - A "black hole" that discards all data (useful in scripts!)

Remember: Everything is a file! Your hard disk is the file /dev/sda.

/proc (Process Information)

A virtual file system that provides information about running processes and the kernel. These aren't real files on disk—they're created on-the-fly.

  • /proc/cpuinfo - CPU information
  • /proc/meminfo - Memory information
  • /proc/[PID] - Information about process with ID [PID]

/sys (System Information)

Another virtual file system with kernel and device information, similar to /proc but more organized.

/boot (Boot Files)

Files needed to boot the system:

  • Linux kernel
  • Bootloader configuration (GRUB)

/mnt and /media (Mount Points)

/mnt and /media are used to temporarily mount external storage devices like USB drives.

In Windows, when you plug in a USB, it gets a drive letter (E:, F:). In Linux, it gets "mounted" to a directory like /media/usb.

Understanding Paths

Paths in Linux use forward slashes / to separate directories (Windows uses backslashes \).

Path Type Example Description
Absolute Path /home/ec2-user/documents/file.txt Starts from root (/), shows full location
Relative Path documents/file.txt Relative to current directory

Special Symbols in Linux

Symbol Meaning Example
/ Root directory Top level of file system
~ User's home directory ~ = /home/ec2-user
. Current directory ./script.sh = run script in current folder
.. Parent directory (one level up) cd .. = go up one level

Navigating Directories

Let's say you're currently in /home/ec2-user and want to go to the root directory: 

# Check where you are now
pwd
Output: /home/ec2-user

# Go up one level to /home
cd ..
pwd
Output: /home

# Go up one more level to /
cd ..
pwd
Output: /

# List everything at root level
ls
Output: bin  boot  dev  etc  home  lib  opt  proc  root  sbin  sys  tmp  usr  var

✅ Pro Tip:

The pwd command (Print Working Directory) shows your current location. Use it often when learning!

⚖️ Windows vs Linux - What's Different?

Two Different Worlds

If you're coming from Windows, Linux will feel different. Let's compare them side-by-side:

Figure 7: Windows (drive-based) vs Linux (single root)

Key Differences Table

Feature Windows Linux
File System Root Multiple drives: C:, D:, E: Single root: /
Path Separator Backslash: C:\Users\John Forward slash: /home/john
Case Sensitivity Not case-sensitive Case-sensitive
Primary Interface GUI (click and drag) CLI (type commands)
Administrator Account Administrator root
Configuration Registry + config files Text files in /etc
Software Installation Download .exe, double-click Package managers: apt, yum
Devices Drive letters: D:, E: Files in /dev: /dev/sda
Cost Paid license Free and open-source
Security Antivirus needed File permissions, no antivirus needed

Case Sensitivity - A Critical Difference!

This trips up many Windows users:

❌ In Windows:

File.txt = file.txt = FILE.TXT
(All refer to the SAME file)

✅ In Linux:

File.txt ≠ file.txt ≠ FILE.TXT
(These are THREE DIFFERENT files!)

Linux is strictly case-sensitive—File.txt and file.txt are treated as completely different files.

Real-world example: If you type CD /home instead of cd /home, Linux will say "command not found" because CD and cd are different!

GUI vs CLI

Windows is primarily GUI-based:

  • You click on folders to open them
  • You drag files to move them
  • You double-click programs to run them

Linux servers are primarily CLI-based:

  • You type cd folder to open folders
  • You type mv file.txt /home/ to move files
  • You type ./program to run programs

💡 Why CLI for Servers?

GUI requires a lot of resources (RAM, CPU) to display graphics. Servers don't need fancy windows and buttons—they just need to run applications and serve data. CLI is faster, uses fewer resources, and is easier to automate with scripts.

How Software Installation Differs

In Windows:

  1. Open browser
  2. Search for "download Git"
  3. Download .exe file
  4. Double-click to install
  5. Click Next, Next, Finish

In Linux:

sudo yum install git -y

One command! The package manager (yum in this case) knows where to find Git, downloads it, installs it, and configures it automatically.

Windows Equivalent to Linux Directories

C:\Program Files /usr, /opt

C:\Users\John /home/john
C:\Users\Administrator /root

🌐 Linux Flavors (Distributions)

One Kernel, Many Flavors

Remember, Linux is just the kernel. Different groups take the Linux kernel, add their own tools and software, and create complete operating systems called distributions or distros.

It's like ice cream: vanilla is the base flavor (Linux kernel), but you can add different toppings to create different varieties!

Figure 8: Major Linux distribution families

Why So Many Distros?

Because Linux is open-source, anyone can create their own version! Different distros are optimized for different purposes:

  • Some for servers (stable, secure)
  • Some for desktops (user-friendly, pretty)
  • Some for security testing (hacking tools pre-installed)
  • Some for old computers (lightweight)

Popular Linux Distributions

Distribution Purpose Who Uses It
Amazon Linux AWS EC2 instances AWS cloud engineers, optimized for AWS
Ubuntu General purpose, beginner-friendly Developers, students, desktop users
CentOS / Rocky Linux Enterprise servers Companies running production servers
Red Hat Enterprise Linux (RHEL) Enterprise servers with paid support Large corporations, banks
Fedora Desktop, testing new features Developers, enthusiasts
Debian Server, very stable Experienced Linux users
Kali Linux Cybersecurity, penetration testing Ethical hackers, security professionals
Parrot OS Security testing, privacy-focused Security researchers
Alpine Linux Docker containers, minimal DevOps engineers (very small size)

Package Managers by Distro

Different Linux distributions use different package managers to install software.

Distro Family Package Manager Install Command
Debian/Ubuntu apt sudo apt install nginx
Red Hat/CentOS/Amazon Linux yum or dnf sudo yum install nginx
Arch Linux pacman sudo pacman -S nginx
Alpine Linux apk apk add nginx

💡 For AWS Users:

When you launch an EC2 instance, you'll typically choose:

  • Amazon Linux 2: AWS's own distro, free tier eligible, includes AWS CLI pre-installed
  • Ubuntu Server: Very popular, great for web applications
  • Red Hat: If you need commercial support (costs extra)

What About Kali Linux and Parrot OS?

These are special distros for cybersecurity professionals. They come with hundreds of pre-installed hacking tools for:

  • Penetration testing (finding security vulnerabilities)
  • Network analysis
  • Password cracking
  • Wireless security testing

⚠️ Important Note:

Kali and Parrot are for ethical hacking only—authorized security testing with permission. Using these tools maliciously is illegal!

🔌 Connecting to Linux EC2 Instance

Your First Linux Experience in AWS

When you launch a Linux EC2 instance in AWS, you can connect to it using SSH (Secure Shell). Let's understand what you see when you connect.

EC2 Instance Connect

AWS provides a browser-based SSH client called EC2 Instance Connect. This is the easiest way to connect to your Linux instance without needing external software.

✅ When to Use EC2 Instance Connect:

  • Your instance has a public IP address
  • You're using a Linux-based AMI (Amazon Linux, Ubuntu)
  • You don't have SSH client software installed
  • You launched the instance without a key pair

Understanding the Linux Prompt

When you connect, you'll see something like this:

[ec2-user@ip-172-31-10-88 ~]$

Let's decode this:

Part Meaning
ec2-user Current logged-in username
@ Separator (at)
ip-172-31-10-88 Hostname (based on private IP)
~ Current directory (tilde = home directory)
$ Standard user (not root)

User Accounts in Linux

Linux is a multi-user operating system where each user has their own account and home directory.

When you log in as ec2-user, you're in /home/ec2-user. This is your personal workspace.

Standard User vs Root User

There are two types of users:

User Type Symbol Permissions Home Directory
Standard User $ Limited (can't modify system files) /home/username
Root User # Full control over everything /root

To switch to root user temporarily:

sudo su -

The prompt changes to:

[root@ip-172-31-10-88 ~]#

Notice the # symbol—this means you're now root (administrator)!

❌ Warning:

Be extremely careful when you're root! You can delete critical system files with no warning. With great power comes great responsibility!

Basic Navigation Commands

Try these commands when you connect to your EC2 instance:

# Check where you are
pwd
Output: /home/ec2-user

# List files in current directory
ls
Output: (shows files and folders)

# Go to root directory
cd /

# List everything at root
ls
Output: bin  boot  dev  etc  home  lib  opt  proc  root  sbin  sys  tmp  usr  var

# Go back to your home directory
cd ~

# Check again where you are
pwd
Output: /home/ec2-user

The Tilde (~) Symbol

The tilde ~ is a shortcut for your home directory:

  • For ec2-user, ~ means /home/ec2-user
  • For root, ~ means /root

So instead of typing:

cd /home/ec2-user/documents

You can type:

cd ~/documents

Much shorter!

📝 Overall Summary

Let's recap everything we learned about Linux fundamentals:

  • Operating Systems: An OS is software that acts as a bridge between users/applications and hardware. It manages CPU, memory, storage, and devices. Without an OS, applications can't run.
  • Unix History (1960s): Unix was the first multi-user, multi-tasking OS developed using C programming. It introduced the hierarchical file system and "everything is a file" philosophy. However, it was proprietary and expensive.
  • Linux Birth (1991): Linus Torvalds created the Linux kernel as a free alternative to Unix. Combined with GNU tools (shell, utilities, libraries), it formed a complete open-source operating system. Linux is maintained by a global community.
  • Linux Architecture: Layered system from bottom to top: Hardware → Kernel (core OS) → System Libraries (helper code) → Shell (command interpreter) → Utilities and Applications. The kernel manages all hardware access.
  • File System Hierarchy: Linux uses a single root directory (/) instead of multiple drives. Everything branches from /. Key directories: /home (user files), /etc (configuration), /var (logs), /bin (commands), /root (admin home), /tmp (temporary files).
  • Everything is a File: In Linux, devices, directories, processes, and regular files are all treated as files. This provides a unified way to interact with the system.
  • Windows vs Linux: Windows uses drive letters (C:, D:) and backslashes; Linux uses single root (/) and forward slashes. Windows is case-insensitive; Linux is case-sensitive. Windows is GUI-first; Linux servers are CLI-first.
  • Linux Distributions: Different groups create Linux distros for different purposes. Popular ones: Amazon Linux (AWS), Ubuntu (general), CentOS/RHEL (enterprise), Kali (security testing). Each uses different package managers (apt, yum, dnf).
  • CLI Importance: Linux servers use command-line interfaces because they're faster, more efficient, and easier to automate than GUIs. Cloud engineers must be comfortable with CLI.
  • Case Sensitivity: File.txt and file.txt are different files in Linux. This is a common source of errors for Windows users transitioning to Linux.
  • EC2 Connection: When you SSH into an EC2 instance, you land in /home/ec2-user. The prompt shows username@hostname, current directory (~), and user type ($=standard, #=root). Use pwd to check location, ls to list files, cd to navigate.
  • User Types: Standard users (like ec2-user) have limited permissions. Root user has complete control. Use sudo su - to become root temporarily, but be careful—you can break the system!

Understanding these Linux fundamentals is crucial before diving into commands, file permissions, process management, and shell scripting in upcoming sessions.

❌ Issue: Using backslashes like Windows: cd \home\ec2-user

Solution: Linux uses forward slashes: cd /home/ec2-user

Project 2: Understanding User Types and Switching

🎯 Objective: Understand the difference between standard user and root user

⏱️ Time: 15-20 minutes

💰 Cost: Free tier eligible

Step-by-Step Instructions

Step 1: Check Current User

# Check who you are
whoami
# Output: ec2-user

# Check your home directory
echo $HOME
# Output: /home/ec2-user

Step 2: Switch to Root User

# Become root user
sudo su -

# Notice the prompt changed from $ to #
# Check who you are now
whoami
# Output: root

# Check root's home directory
echo $HOME
# Output: /root

pwd
# Output: /root

Step 3: Explore Root's Home

# As root, list files in root's home
ls -la

# Try to go to ec2-user's home
cd /home/ec2-user
ls
# You can access it! Root can access everything

Step 4: Switch Back to Standard User

# Exit root user
exit

# Check who you are now
whoami
# Output: ec2-user

# Notice prompt changed back to $

Step 5: Test Permissions

# As ec2-user, try to access /root
cd /root
# Output: Permission denied

# This demonstrates that standard users can't access root's home

Verification

✅ You Should Understand:

  • $ symbol means standard user
  • # symbol means root user
  • Root can access everything, standard users have limits
  • sudo su - switches you to root
  • exit brings you back to standard user

Clean Up

Make sure you exit back to ec2-user before ending the session:

# If you're still root, exit
exit

# Verify you're ec2-user
whoami
